# Фаззинг Arca

Два уровня, оба детерминированно воспроизводимы:

1. **Структурный мутационный тест** — часть обычного `cargo test`
   (`crates/arca-xray/src/tests/mutation.rs`). Мутирует все файлы корпуса:
   байты, поля заголовков ZIP/CFB граничными значениями, распакованное
   содержимое XML-частей (DOCTYPE, сущности, вложенность, огромные атрибуты) с
   перепаковкой. Проверяет: нет паник, инварианты вердикта, wire-раундтрип,
   детерминизм сканера, контракт и идемпотентность стерилизатора.

   ```sh
   ARCA_FUZZ_ITERS=30000 ARCA_FUZZ_SEED=1 \
       cargo test --release -p arca-xray mutation_fuzz
   ```

   Упавший вход сохраняется в `$TMPDIR/arca-fuzz-failure-<sha>.bin`, путь
   печатается в сообщении. Раз в неделю то же с большим числом итераций и новым
   сидом запускает workflow `fuzz`.

   Те же правила (`ARCA_FUZZ_ITERS` — мутантов на файл-затравку, `ARCA_FUZZ_SEED`, по умолчанию
   малые числа, чтобы `cargo test` оставался быстрым) у двух других детерминированных тестов,
   которым тоже не нужен nightly:

   | тест | что мутирует и что проверяет |
   |---|---|
   | `crates/arca-image/tests/mutation.rs` | PNG, JPEG, GIF, BMP: обход чанков PNG (поля заголовка граничными значениями, CRC чинится и не чинится), маркеров JPEG, враждебные блоки EXIF во вставленном `APP1`. Нет паник; картинка ровно `w·h·4` байт и не больше `max_out_side` (ограниченный вывод); формат по сигнатуре и по декодеру совпадают; детерминизм; раундтрип по проводу; стерильный PNG читается обратно |
   | `crates/arca-container/tests/jet_mutation.rs` | базы Access (`.mdb`, `.accdb`) постранично: поля заголовков страниц, копирование и обмен страниц, обрезка по границе страницы. Нет паник; число объектов, столбцов и размер значений в пределах лимитов читателя; детерминизм |

   ```sh
   ARCA_FUZZ_ITERS=200000 ARCA_FUZZ_SEED=1 cargo test --release -p arca-image --test mutation
   ARCA_FUZZ_ITERS=200000 ARCA_FUZZ_SEED=1 cargo test --release -p arca-container --test jet_mutation
   ```

2. **libFuzzer (`cargo-fuzz`)** — этот каталог. Отдельный крейт вне workspace,
   потому что нужен nightly и санитайзеры.

   | цель | что проверяет |
   |---|---|
   | `scan` | сканер не паникует, вердикт согласован с находками, результат детерминирован |
   | `sanitize` | стерильная копия всегда проверена повторно и идемпотентна |
   | `wire` | декодеры конверта и всех полезных нагрузок (отчёт, стерильный документ, просмотр, страница, картинка; то, что хост читает у недоверенного гостя), в том числе с бюджетом: принятое при малом бюджете принимается при большем и даёт то же значение, принятое при жёстких лимитах — при обычных |
   | `zip`, `cfb`, `xml` | контейнеры и безопасный XML-ридер по отдельности |
   | `preview` | все парсеры просмотра за определителем формата (DOCX/XLSX/PPTX, DOC/XLS/PPT, ODF, RTF, PDF, MSG, VSDX, текст) и оба писателя стерильной копии: нет паник и зависаний, результат детерминирован и переживает провод, «копия» читается обратно |
   | `decrypt` | расшифровка Office (standard/agile) и PDF (R2–R6): данные шифрования недоверенные |
   | `image` | любые байты, формат по сигнатуре, как зовёт движок: ограниченный вывод, детерминизм, раундтрип по проводу, стерильный PNG |
   | `png`, `jpeg`, `gif`, `bmp` | то же, но сигнатура формата дописывается, если её нет: фаззер работает с чанками, маркерами, LZW, RLE, а не угадывает заголовок |
   | `exif` | читатель EXIF так, как до него доходит файл: враждебный блок TIFF в `APP1` JPEG или в чанке `eXIf` PNG |
   | `jet` | базы Access: открытие, каталог, определения таблиц, строки; заголовок подправляется, чтобы работать со страницами, а не с сигнатурой; пределы и детерминизм |
   | `pdf` | сканер, чтение, постраничная отрисовка и стерильная копия для PDF (заголовок `%PDF-` дописывается): нет паник и зависаний, детерминизм, копия читается обратно |

   ```sh
   cargo install cargo-fuzz --version 0.12.0 --locked
   mkdir -p fuzz/corpus/scan
   ARCA_CORPUS_OUT=$PWD/fuzz/corpus/scan cargo test -p arca-xray dump_corpus   # затравка
   ARCA_WIRE_OUT=$PWD/fuzz/corpus/wire   cargo test -p arca-xray dump_wire_seeds
   cd fuzz && cargo +nightly fuzz run scan -- -dict=dictionaries/ooxml.dict -max_total_time=300
   cd fuzz && cargo +nightly fuzz run jpeg -- -dict=dictionaries/images.dict -max_total_time=300   # затравка: crates/arca-image/tests/fixtures
   ```

   Корпуса, артефакты и `target/` в репозиторий не попадают (`.gitignore`):
   в них могут оказаться вредоносные образцы.

> Статус: цели собираются против актуальных API (проверено `cargo check` с заглушкой
> `libfuzzer-sys`: сам `libfuzzer-sys` и nightly в среде разработки недоступны) и проходят на всех
> файлах `tests/fixtures` и `crates/arca-image/tests/fixtures` вместе с их мутациями через заглушку
> `fuzz_target!`, без паник и нарушений инвариантов. Но **сами по себе в `libFuzzer` (с покрытием)
> ещё ни разу не запускались**. Первый настоящий прогон — задача CI (`.github/workflows/fuzz.yml`:
> на PR 60 с на цель, раз в неделю 30 мин; отдельное задание `mutation` гоняет три детерминированных
> теста с большим числом итераций) или машина с nightly и доступом к crates.io. Реальные
> вредоносные образцы в репозиторий не добавляются и здесь не прогонялись.
