## Архитектура защиты: Как это работает

### Зачем всё это

Документ Word, Excel или PDF — это сложная составная программа, а не просто текст. Внутри файла могут содержаться автоисполняемые макросы, скрипты, ссылки на внешние серверы для эксфильтрации NTLM-хэшей или искажённые бинарные структуры, эксплуатирующие переполнения памяти в парсерах операционной системы. Обычные офисные пакеты открывают файлы на доверии, оставаясь ключевым вектором целевых атак.

Arca исходит из противоположного постулата: **файл враждебен, пока не доказано обратное**. Приложение не пытается угадать намерения автора, а изолирует процесс разбора так, чтобы даже самый изощрённый эксплойт нулевого дня не мог нанести ущерб устройству.

### Три эшелона безопасности

1. **100% Safe Rust:** Весь код парсеров написан на Rust с флагом `#![forbid(unsafe_code)]` без использования C/C++ библиотек. Это гарантирует отсутствие ошибок управления памятью (buffer overflow, use-after-free, double free), лежащих в основе большинства эксплойтов.
2. **Одноразовая эфемерная Wasm-песочница:** Разбор документа выполняется не в процессе приложения, а внутри интерпретатора WebAssembly (`wasmi`). У модуля-гостя **нет ни единой функции импорта**: закрыт доступ к сети, диску, часам реального времени, генераторам псевдослучайных чисел и IPC. Песочница способна лишь производить вычисления в границах своего изолированного блока линейной памяти. По завершении разбора память обнуляется, а инстанс песочницы уничтожается.
3. **Строгие ресурсные квоты:** Действует лимит на любые динамические параметры: глубину вложенности контейнеров, степень сжатия архивов (защита от zip-бомб и Billion Laughs), максимальную аллокацию памяти и бюджет вычислительного времени (CPU fuel). Разбор прерывается мгновенно по токену отмены или жесткому тайм-ауту.

```text
 Входящий файл ─► Системный выбор (Storage Access Framework) ─► Arca (Rust-хост)
                                                                     │
                              1. Проверка криптографического хэша модуля (SHA-256)
                              2. Инициализация чистой Wasm-песочницы с квотами памяти
                              3. Передача байтов документа через изолированный буфер
                                                                     ▼
                                           ┌─── Песочница Wasm (0 импортов, 0 сети) ───┐
                                           │  «Рентген»: сигнатурный анализ формата,   │
                                           │  декомпиляция VBA/XLM, извлечение связей,  │
                                           │  скрытых объектов, метаданных и разметки  │
                                           └─────────────────────┬─────────────────────┘
                                                                 ▼
                              4. Приём отчёта через wire-кодек под защитными лимитами
                                 (гостевой Wasm-модуль априори считается скомпрометированным)
                              5. Уничтожение песочницы, очистка памяти через zeroize
                                                                 ▼
                                                    Экран отчёта и вердикт Arca
```

> [!NOTE]
> Хост песочницы **не доверяет даже ответу песочницы**. Отчёт парсера валидируется внешним декодером со строгими ограничениями на аллокации. Стерильная копия документа проверяется хостом независимо: сверяется контрольная сумма SHA-256 с данными отчёта, а в архивах ZIP проверяются имена частей на отсутствие оставшихся макросов, OLE-объектов или ActiveX.

## Возможности ядра Arca 0.6.0

### 1. «Рентген безопасности» и классификация макросов (ABI 8)
Перед открытием любого документа Arca проводит сигнатурный анализ (формат распознаётся исключительно по байтовым сигнатурам, а не по расширению имени файла). В версии 0.6.0 «Рентген» не просто находит активный код, но и объясняет его поведение:
* **Анализ макросов и скриптов:** VBA, Excel 4.0 (XLM), DDE-формулы, вложенные объекты OLE и элементы ActiveX, формулы Equation Editor, JavaScript и действия Launch в PDF.
* **Категории намерений:** каждому фрагменту кода присваивается вердикт: **безобидный**, **подозрительный** или **вредоносный** с указанием конкретных процедур и действий (скачивание файлов, запуск процессов, манипуляции с реестром, сбор сведений об окружении, обфускация через `Chr`).
* **Обращения во внешний контур:** обнаружение внешних шаблонов, скрытых трекинг-пикселей, UNC-путей вида `\\server\...` (предотвращение утечки NTLM-хэшей) и опасных схем URI (`ms-msdt:`, `mhtml:`, `search-ms:`).
* **Скрытое содержимое:** скрытые строки, листы и слайды, белый шрифт на белом фоне, оверлеи и данные за пределами контейнеров (полиглоты).
* **Криминалистические метаданные:** авторство, организация, имя рабочей станции, локальные файловые пути, принтеры, история ревизий и скрытые комментарии.

### Итоговые вердикты безопасности

| Вердикт | Индикатор | Значение |
|---|:---:|---|
| **`Rejected`** | ⛔ | Файл представляет критическую угрозу (zip-бомба, path traversal, замаскированный бинарник PE) и блокируется. |
| **`ActiveContentNeutralized`**| ⚠️ | Обнаружено активное содержимое (макросы, эксплойты) или критические внешние ссылки. |
| **`Unverified`** | ❓ | Документ невозможно проверить полностью (шифрование без пароля, повреждение структуры). |
| **`HiddenTrackers`** | 👁️ | Текст безопасен, но присутствуют внешние ресурсы или трекинг-пиксели. |
| **`Clean`** | ✅ | Документ проверен **на 100%**, отсутствуют любые подозрительные или недокументированные элементы. |

> [!TIP]
> **Принцип честной верификации:** Arca никогда не присвоит статус `Clean`, если хотя бы один байт документа не был однозначно распознан и разобран. Любое неоднозначное толкование контейнера ведёт к статусу `Unverified`.

### 2. Полигон атак `malware-test` (50 образцов)
В состав проекта входит верифицированный полигон атак ([`tests/malware-test/`](tests/malware-test/)), содержащий 50 обезвреженных образцов ключевых угроз:
* **RCE и эксплойты ридеров (01–30):** CVE-2017-11882 / CVE-2018-0802 (Equation Editor), CVE-2022-30190 (Follina/MSDT), CVE-2021-40444, CVE-2017-0199, CVE-2023-36884, инъекции DDE, XLM auto-open, VBA-дропперы, обфусцированные загрузчики, PDF `util.printf`, PDF embedded EXE, RTF OLE package.
* **Парсерные диверсии и бомбы (31–43):** Zip Slip, zip-бомбы, Billion Laughs, XXE local file read, закольцованные цепочки секторов CFB FAT/MiniFAT, аномальные DIFAT-заголовки, Flate-бомбы в PDF, RTF с 200 000 уровней вложенности.
* **Утечки окружения и фингерпринтинг (44–50):** эксфильтрация NTLM через `INCLUDEPICTURE` и ссылки XLSX, WebDAV SSL шаблоны, фингерпринтинг песочницы из VBA, XLM и PDF JavaScript, трекинг-пиксели.

> Все образцы генерируются процедурно из кода: в репозитории физически отсутствуют боевые бинарные эксплойты.

### 3. Стерильная копия в один тап
Для форматов OOXML (`docx`, `xlsx`, `pptx`), OpenDocument (`odt`, `ods`, `odp`), Visio и PDF приложение формирует **стерилизованную копию**:
* Удаляются макросы, внешние ссылки, история правок, комментарии и персональные метаданные.
* Для растровых изображений (`png`, `jpeg`, `gif`, `bmp`) стерильная копия генерируется как **новый PNG, перерисованный из сырых пикселей**: отсекаются метаданные EXIF, GPS-координаты, миниатюры и скрытые хвосты файлов (подробнее — в [`docs/IMAGES.md`](docs/IMAGES.md)).
* Готовая копия проходит **повторный автоматический рентген-контроль** в песочнице перед сохранением.

### 4. Безопасный страничный просмотр
* **Текстовые документы и таблицы:** форматирование, стили, цвета, таблицы, колонтитулы и параметры страниц (DOCX, ODT, RTF, старые бинарные DOC/XLS/PPT).
* **Слайды и презентации (PPTX / ODP):** отрисовка фонов слайдов, картинок-заливок (`blipFill`, `draw:fill="bitmap"`) и **диаграмм на слайдах PPTX** (столбчатые, линейные, круговые, кольцевые, диаграммы с областями) на основе кэшированных данных без разбора внешних таблиц Excel.
* **Схемы Visio (VSDX и бинарный VSD):** векторная геометрия фигур, соединительные линии со стрелками, скруглённые углы и поддержка палитр тем из `visio/theme/theme1.xml`.
* **Базы данных Microsoft Access (MDB / ACCDB):** просмотр структуры таблиц, типов полей, индексов и интерактивная **схема связей (ER-диаграмма)** с трассировкой отношений `1` к `∞` по зазорам колонок.
* **Картинки в параноидальном режиме:** раскодируются только собственным безопасным Rust-декодером в Wasm-песочнице без привлечения системных библиотек ОС.

## Сборка и тестирование

### 1. Ядро Rust и модульные тесты
Для сборки ядра требуется Rust 1.97.0 (зафиксирован в `rust-toolchain.toml`).

```sh
# Прогон модульных и интеграционных тестов ядра
cargo test --workspace

# Компиляция Wasm-модуля гостя для песочницы
bash tools/build-guest.sh

# Сквозное тестирование Wasm-гостя в песочнице на тестовом корпусе
ARCA_GUEST_XRAY_WASM=$PWD/target/wasm32-unknown-unknown/guest/arca_guest_xray.wasm \
ARCA_CORPUS_DIR=$PWD/tests/fixtures \
    cargo test --release -p arca-guest-xray --test e2e_sandbox

# Запуск полигона malware-test в реальной Wasm-песочнице
bash tools/check-malware-lab.sh
```

### 2. Сборка Android APK
Для сборки пакета требуются JDK 17+, Android SDK (`platforms;android-36`, `build-tools;36.0.0`) и NDK-компоновщик. Сборка не требует Gradle:

```sh
# Компиляция Wasm-гостя
bash tools/build-guest.sh

# Верификация ресурсов, компиляция против API 26 и 36, линты
bash tools/android/check-android.sh

# Запуск JNI-тестов на JVM с проверкой -Xcheck:jni
ARCA_GUEST_WASM=$PWD/target/wasm32-unknown-unknown/guest/arca_guest_xray.wasm \
ARCA_CORPUS_DIR=$PWD/tests/fixtures bash android/host-test/run.sh

# Локальная сборка тестового APK с одноразовым ключом
ARCA_THROWAWAY_KEY=1 tools/android/build-apk.sh
```

Подробное руководство по сборке, ключам и тестированию — в [`docs/ANDROID.md`](docs/ANDROID.md) и [`docs/RELEASING.md`](docs/RELEASING.md).

### 3. Сборка клиента iOS
Сборка выполняется на macOS (Xcode 15+, Swift 5.9+):

```sh
# Полный цикл проверки клиента iOS: сборка XCFramework, компиляция и тесты ArcaKit
bash tools/ios/check-ios.sh
```
