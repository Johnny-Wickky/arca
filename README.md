# arca
Arca — Параноидально безопасный FOSS-пакет для iOS и Android. Просмотр Office, Visio 3D и Access в изолированной Wasm-песочнице на ядре Rust. Эстетика уровня Apple, zero-trust и нулевая телеметрия.

Каждый файл считается враждебным эксплойтом: он разбирается memory-safe
кодом на Rust внутри одноразовой WebAssembly-песочницы без доступа к сети,
файлам, часам и IPC.

*A paranoid, 100% FOSS document viewer for Android and iOS. Every file is
parsed by safe Rust inside a single-use, zero-import WebAssembly sandbox.*

**Android-приложение:** готовые подписанные сборки — в
[Releases](https://github.com/Johnny-Wickky/arca/releases) (Android 8–16, телефоны,
планшеты, складные устройства). Что умеет первая версия и чего ещё нет —
[`docs/releases/v0.1.0.md`](docs/releases/v0.1.0.md); справочник по Android-части —
[`docs/ANDROID.md`](docs/ANDROID.md).

## Как это работает — простыми словами

### Зачем всё это

Документ Word, Excel или PDF — это не просто текст. Внутри может быть макрос,
который запустит программу, ссылка на чужой сервер, которая сообщит, что вы
открыли файл, или специально искажённая структура, ломающая программу-просмотрщик
и дающая атакующему контроль над телефоном. Обычные офисные приложения
разбирают такие файлы «на доверии», и именно через них годами идут атаки.

Arca исходит из обратного: **любой файл — потенциально враждебный**. Приложение
не пытается угадать, «хороший» он или «плохой», а устроено так, чтобы даже
плохой файл ничего не мог сделать.

### Три слоя защиты

1. **Безопасный язык.** Весь код разбора написан на Rust без `unsafe` и без
   C/C++. Это исключает целый класс ошибок (переполнение буфера, обращение к
   освобождённой памяти), на которых строится большинство эксплойтов
   просмотрщиков документов.
2. **Одноразовая песочница.** Разбор файла выполняется не в самом приложении, а
   внутри WebAssembly-модуля, который запускает интерпретатор `wasmi`. У этого
   модуля **нет ни одной функции для связи с внешним миром**: ни сети, ни файлов,
   ни часов, ни случайных чисел. Он умеет только считать внутри своей
   ограниченной памяти. Если в парсере и найдётся ошибка, ему некуда «выйти».
   После каждого запуска песочница уничтожается, а её память обнуляется.
3. **Жёсткие лимиты.** На всё, что зависит от файла, есть потолок: размер,
   глубина вложенности, степень сжатия (против zip-бомб), память и «топливо»
   процессора. Разбор можно отменить за миллисекунды, а вечное зависание
   невозможно из-за дедлайна.

Приложению не нужно разрешение `INTERNET`, а в коде нет телеметрии, рекламы и
аналитики. Ссылки на документе только **перечисляются** в отчёте, и по ним никто
не ходит; открыть `http`/`https`-ссылку во внешнем браузере можно лишь отдельным
явным действием, после того как показан её полный адрес.

### Что происходит, когда вы открываете файл

```text
 файл ─► системный выбор файла ─► Arca (Rust-ядро)
                                      │
                       1. проверяем, что модуль-парсер подлинный (SHA-256)
                       2. создаём пустую песочницу с лимитами
                       3. кладём в неё байты файла
                                      ▼
                    ┌─── песочница (Wasm, ноль связи с миром) ───┐
                    │  «Рентген»: определяет формат по           │
                    │  сигнатурам, ищет макросы, внешние         │
                    │  ссылки, скрытое, метаданные               │
                    └────────────────────┬───────────────────────┘
                                         ▼
                      4. забираем отчёт, проверяя каждую границу
                         (гость считается потенциально взломанным)
                      5. уничтожаем песочницу, обнуляем память
                                         ▼
                           вердикт + отчёт на экране
```

Ключевая деталь: хост **не доверяет даже ответу песочницы**. Отчёт декодируется
отдельным кодеком с лимитами, как если бы его прислал злоумышленник.

Если файл не отклонён, **просмотр строится так же**: в новой песочнице гость-парсер
превращает документ в простую структуру (абзацы, таблицы, слайды) без активного
содержимого, и приложение лишь рисует её текстом. Ссылки и внешние ресурсы не
загружаются, ничего не исполняется, скрытое помечается.

### «Рентген безопасности»

Перед показом документа Arca сообщает, что в нём нашлось. Формат определяется
**по содержимому, а не по расширению**: файл `.docx`, который на деле
исполняемый, будет распознан. Ищется следующее:

- **Активное содержимое:** макросы VBA (с исходным кодом), старые макросы Excel
  4.0, DDE, встроенные OLE-объекты и ActiveX, эксплойты Equation Editor,
  JavaScript и запуск программ в PDF.
- **Обращения наружу:** удалённые шаблоны, трекинг-пиксели, пути вида `\\сервер\…`
  (через них утекает NTLM-хэш), опасные схемы ссылок.
- **Скрытое:** скрытые листы, строки и слайды, белый текст на белом, данные,
  спрятанные в «хвосте» файла, файлы-полиглоты.
- **Утечки приватности:** автор, организация, имя компьютера, локальные пути,
  принтер, история правок, комментарии.
- **Атаки на формат:** zip-бомбы, Zip Slip, XXE, Billion Laughs, подмена типа.

Итог — один из пяти вердиктов:

| вердикт | значит |
|---|---|
| `Rejected` | файл опасен сам по себе (бомба, обход путей, исполняемый файл), не открывается |
| `ActiveContentNeutralized` | есть активная нагрузка или критическая внешняя ссылка |
| `Unverified` | часть файла проверить не удалось (шифрование, повреждение) |
| `HiddenTrackers` | есть внешнее содержимое, например трекеры |
| `Clean` | проверено **целиком**, ничего опасного нет |

Важное правило: Arca **не говорит «Чистый» о том, чего не проверила**. Если часть
файла не разобралась, будет `Unverified`. А чтобы спрятать макрос, недостаточно
завалить отчёт тысячами безобидных находок: вердикт считается по фактам
независимо от лимита на длину отчёта.

### Стерильная копия в один тап

Для документов OOXML (`docx`, `xlsx`, `pptx`, …) можно создать **очищенную копию**:
без макросов, внешних связей, ревизий, комментариев и метаданных. Копия
собирается заново, а затем **проверяется тем же рентгеном ещё раз**. Если в ней
осталось что-то опасное, Arca её не выдаст. Результат одинаков при каждом
запуске. Поделиться копией можно через системное меню.

### Из чего состоит проект

| часть | роль |
|---|---|
| `arca-digest` | SHA-256 и CRC-32, без зависимостей |
| `arca-container` | безопасное чтение ZIP, OLE2 и XML со всеми лимитами |
| `arca-abi` | «договор» между приложением и песочницей: как передать файл и получить ответ |
| `arca-xray` | сам «рентген» и стерилизатор |
| `arca-preview` | безопасный просмотр: DOCX/DOC, XLSX/XLS, PPTX/PPT, ODF, RTF, PDF (текст), MSG, текст/CSV → нейтральная модель «абзацы · таблицы · слайды» |
| `arca-guest-xray` | `arca-xray` и `arca-preview`, собранные в Wasm-модуль для песочницы |
| `arca-sandbox` | запуск Wasm-модулей: проверка подлинности, лимиты, отмена, дедлайн |
| `arca-engine` | безопасная прослойка между приложением и песочницей: лимиты по устройству, коды результата, JSON страницами |
| `arca-jni` | JNI-мост для Android: `libarca_jni.so` (единственный нативный код приложения) |
| `arca-attribution` | указание создателей, форки и экран «О проекте» |
| `android/` | приложение для Android: Java без AndroidX и Gradle, пакет собирается `tools/android/build-apk.sh` |
| `app/` | заготовка клиента для iOS (план) |

Хост песочницы **не содержит ни одного парсера документов**: всё, что читает
файлы, живёт только внутри песочницы.

### Что уже сделано и что дальше

Готовы «ядро безопасности» (проверка и очистка), **безопасный просмотр** основных
форматов и **приложение для Android**. Дальше:

1. **Просмотр Visio (включая 3D) и Access** — рентген для них уже есть, просмотра пока нет.
2. **Рисование страниц**, а не только содержания: сейчас Arca показывает текст, таблицы и
   слайды как структуру, а картинки и диаграммы заменяет отметкой.
3. **iOS-клиент** на том же ядре (`app/`).
4. **Складные устройства с учётом шарнира и позы** — для этого понадобится
   Jetpack WindowManager, сейчас приложение сознательно без AndroidX.
5. **Проверка на прочность:** расширенный фаззинг парсеров, сравнение с независимыми
   реализациями и прогон на реальных вредоносных образцах в изолированной среде.

Интерпретатор `wasmi` выбран вместо быстрых JIT-движков намеренно: iOS запрещает
сторонним приложениям исполнять сгенерированный код, а интерпретатор к тому же
проще аудировать.

### Поддержка и атрибуция

Arca бесплатна и без рекламы. Проект живёт на пожертвованиях, поэтому лицензия
(AGPL v3 с дополнительными условиями) требует, чтобы форки сохраняли указание
оригинальных создателей и ссылку на их поддержку на экране «О проекте». Свою
ссылку форк может добавить рядом (`fork_attribution.toml`).

## Что уже умеет ядро

- Определяет формат только по сигнатурам и отвергает zip-бомбы, Zip Slip,
  XXE, Billion Laughs, глубокую вложенность, полиглоты, расхождения парсеров
  и замаскированные исполняемые файлы.
- Находит и показывает как текст, ничего не исполняя: VBA (с исходниками),
  XLM / Excel 4.0, DDE (в том числе обфусцированный), OLE / ActiveX / пакеты,
  эксплойты Equation Editor, JavaScript и Launch в PDF, удалённые шаблоны,
  трекинг-пиксели, UNC-пути (утечки NTLM), `ms-msdt:` и т. п.
- Показывает криминалистические метаданные: автор, организация, компьютер,
  локальные пути, принтер, время правки, ревизии, комментарии.
- **Стерильная копия в один тап** (OOXML): без макросов, внешних связей,
  ревизий, комментариев и метаданных, с повторной проверкой результата.
- Не говорит «Чистый» о том, чего не проверил: зашифрованная или не
  разобранная часть даёт вердикт `Unverified`, а наводнение безобидными
  находками не может спрятать решающую.
- **Показывает содержимое документа** (Word, Excel, PowerPoint — в том числе
  старые `.doc`/`.xls`/`.ppt`, OpenDocument, RTF, PDF как текст, письма Outlook, текст и
  CSV) — только чтение: ничего не исполняется, ссылки перечисляются, скрытое помечается,
  всё непрочитанное названо прямо.
- Исполняет всё это внутри песочницы `wasmi` с лимитами памяти (пропорциональна
  файлу, около 96 МиБ для небольшого) и CPU-топлива; топливо выдаётся порциями,
  поэтому разбор можно отменить за миллисекунды и он ограничен по времени
  (`CancelToken`, дедлайн). Модуль-гость закреплён по SHA-256 и не имеет ни
  одного импорта.

## Сборка

```sh
cargo test --workspace
bash tools/build-guest.sh        # = cargo build -p arca-guest-xray --target wasm32-unknown-unknown --profile guest
# сквозные тесты гостя в песочнице (в release: интерпретатор в разы быстрее)
ARCA_GUEST_XRAY_WASM=$PWD/target/wasm32-unknown-unknown/guest/arca_guest_xray.wasm \
ARCA_CORPUS_DIR=$PWD/tests/fixtures \
    cargo test --release -p arca-guest-xray --test e2e_sandbox   # путь к корпусу — абсолютный
cargo run -p arca-xray --example xray -- scan file.docx
# фаззинг: ARCA_FUZZ_ITERS=30000 cargo test --release -p arca-xray mutation_fuzz,
# libFuzzer — см. fuzz/README.md
```

Android-приложение (нужны Android SDK и NDK-компоновщик; подробно — в
[`docs/ANDROID.md`](docs/ANDROID.md)):

```sh
bash tools/build-guest.sh                       # Wasm-гость
bash tools/android/check-android.sh             # ресурсы, манифест, компиляция против API 26 и 36, тесты
ARCA_GUEST_WASM=$PWD/target/wasm32-unknown-unknown/guest/arca_guest_xray.wasm \
    ARCA_CORPUS_DIR=$PWD/tests/fixtures bash android/host-test/run.sh   # JNI на JVM с -Xcheck:jni
# пакет и релиз собирает CI: .github/workflows/android.yml, порядок выпуска — docs/RELEASING.md
```
