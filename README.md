# arca
Arca — параноидально безопасный FOSS-просмотрщик документов на ядре Rust: Office, OpenDocument, PDF, RTF, письма Outlook, картинки, базы Access и рисунки Visio (с геометрией, цветами и соединителями) в изолированной Wasm-песочнице. Нулевая телеметрия, без разрешения на сеть. Доступны нативные приложения для Android и iOS.

Каждый файл считается враждебным эксплойтом: он разбирается memory-safe
кодом на Rust внутри одноразовой WebAssembly-песочницы без доступа к сети,
файлам, часам и IPC.

*A paranoid, 100% FOSS document viewer. Every file is parsed by safe Rust inside a
single-use, zero-import WebAssembly sandbox. Native applications for Android and iOS.*

**Android-приложение:** готовые подписанные сборки — в
[Releases](https://github.com/Johnny-Wickky/arca/releases) (Android 8–16, телефоны,
планшеты, складные устройства).
* **Как распространяется сейчас:** подписанный APK в GitHub Releases. Публикация в каталогах F-Droid и Google Play запланирована.
* **Обновления:** в приложении нет самозагрузчика и нет сети. Новую версию ставят вручную поверх старой; Android принимает её только если пакет подписан тем же релизным ключом.
* **Статус тестирования:** автоматические проверки и фаззинг идут в CI (см. [`docs/ANDROID.md`](docs/ANDROID.md) §6). Ручное тестирование на физических устройствах проводилось для версии 0.1.5; для версий 0.2.x верификация выполняется через эмуляторы и автоматические сьюты.
* **История версий:** версии 0.2.2 и 0.2.4 стабилизировали ядро, закрыли краевые случаи парсеров и перевели сборочный тулчейн на чистый Rust. Подробнее — в [заметках к релизам](docs/releases/).

Справочник по Android-части — [`docs/ANDROID.md`](docs/ANDROID.md).

## Как это работает — простыми словами

### Зачем всё это

Документ Word, Excel или PDF — это не просто текст. Внутри может быть макрос,
который запустит программу, ссылка на чужой сервер, которая сообщит, что вы
открыли файл, или специально искажённая структура, ломающая программу-просмотрщик
и дающая атакующему контроль над телефоном. Обычные офисные приложения
разбирают такие файлы «на доверии», и именно через них годами идут атаки.

Arca исходит из обратного: **любой файл — потенциально враждебный**. Приложение
не пытается угадать, «хороший» он или «плохой», а устроено так, чтобы даже
плохой файл ничего не мог сделать.

### Три слоя защиты

1. **Безопасный язык.** Весь код разбора написан на Rust без `unsafe` и без
   C/C++. Это исключает целый класс ошибок (переполнение буфера, обращение к
   освобождённой памяти), на которых строится большинство эксплойтов
   просмотрщиков документов.
2. **Одноразовая песочница.** Разбор файла выполняется не в самом приложении, а
   внутри WebAssembly-модуля, который запускает интерпретатор `wasmi`. У этого
   модуля **нет ни одной функции для связи с внешним миром**: ни сети, ни файлов,
   ни часов, ни случайных чисел. Он умеет только считать внутри своей
   ограниченной памяти. Если в парсере и найдётся ошибка, ему некуда «выйти».
   После каждого запуска песочница уничтожается, а её память обнуляется.
3. **Жёсткие лимиты.** На всё, что зависит от файла, есть потолок: размер,
   глубина вложенности, степень сжатия (против zip-бомб), память и «топливо»
   процессора. Разбор можно отменить за миллисекунды, а вечное зависание
   невозможно из-за дедлайна.

Приложению не нужно разрешение `INTERNET`, а в коде нет телеметрии, рекламы и
аналитики. Ссылки на документе только **перечисляются** в отчёте, и по ним никто
не ходит; открыть `http`/`https`-ссылку во внешнем браузере можно лишь отдельным
явным действием, после того как показан её полный адрес.

### Что происходит, когда вы открываете файл

```text
 файл ─► системный выбор файла ─► Arca (Rust-ядро)
                                      │
                       1. проверяем, что модуль-парсер подлинный (SHA-256)
                       2. создаём пустую песочницу с лимитами
                       3. кладём в неё байты файла
                                      ▼
                    ┌─── песочница (Wasm, ноль связи с миром) ───┐
                    │  «Рентген»: определяет формат по           │
                    │  сигнатурам, ищет макросы, внешние         │
                    │  ссылки, скрытое, метаданные               │
                    └────────────────────┬───────────────────────┘
                                         ▼
                      4. забираем отчёт, проверяя каждую границу
                         (гость считается потенциально взломанным)
                      5. уничтожаем песочницу, обнуляем память
                                         ▼
                           вердикт + отчёт на экране
```

Ключевая деталь: хост **не доверяет даже ответу песочницы**. Отчёт декодируется
отдельным кодеком с лимитами (в том числе с общим бюджетом памяти на всё, что он
выделяет), как если бы его прислал злоумышленник. Стерильную копию хост проверяет
сам: пересчитывает её SHA-256 и сверяет с отчётом гостя, а у ZIP-копии смотрит имена
частей (макрос, ActiveX, OLE, вложения не должны остаться). Это недорогая «растяжка»,
а не вторая стерилизация: взломанный гость, ошибающийся тоньше, ею не ловится.

Если файл не отклонён, **просмотр строится так же**: в новой песочнице гость-парсер
превращает документ в простую структуру (абзацы, таблицы, слайды) без активного
содержимого, и приложение лишь рисует её текстом. Ссылки и внешние ресурсы не
загружаются, ничего не исполняется, скрытое помечается.

### «Рентген безопасности»

Перед показом документа Arca сообщает, что в нём нашлось. Формат определяется
**по содержимому, а не по расширению**: файл `.docx`, который на деле
исполняемый, будет распознан. Ищется следующее:

- **Активное содержимое:** макросы VBA (с исходным кодом), старые макросы Excel
  4.0, DDE, встроенные OLE-объекты и ActiveX, эксплойты Equation Editor,
  JavaScript и запуск программ в PDF. У каждого макроса и скрипта есть **объяснение**:
  что он делает (скачивает и запускает, пишет файлы, меняет реестр, читает сведения о
  машине, прячет код) и насколько это похоже на вредоносное — «безобидный», «подозрительный»,
  «вредоносный» — с перечнем действий и процедур, где они встречаются. Даже безобидный макрос
  не делает файл «чистым»: вердикт по активному содержимому не опускается ниже среднего.
- **Обращения наружу:** удалённые шаблоны, трекинг-пиксели, пути вида `\\сервер\…`
  (через них утекает NTLM-хэш), опасные схемы ссылок.
- **Скрытое:** скрытые листы, строки и слайды, белый текст на белом, данные,
  спрятанные в «хвосте» файла, файлы-полиглоты.
- **Утечки приватности:** автор, организация, имя компьютера, локальные пути,
  принтер, история правок, комментарии.
- **Атаки на формат:** zip-бомбы, Zip Slip, XXE, Billion Laughs, подмена типа.

Итог — один из пяти вердиктов:

| вердикт | значит |
|---|---|
| `Rejected` | файл опасен сам по себе (бомба, обход путей, исполняемый файл), не открывается |
| `ActiveContentNeutralized` | есть активная нагрузка или критическая внешняя ссылка |
| `Unverified` | часть файла проверить не удалось (шифрование, повреждение) |
| `HiddenTrackers` | есть внешнее содержимое, например трекеры |
| `Clean` | проверено **целиком**, ничего опасного нет |

Важное правило: Arca **не говорит «Чистый» о том, чего не проверила**. Если часть
файла не разобралась, будет `Unverified`. А чтобы спрятать макрос, недостаточно
завалить отчёт тысячами безобидных находок: вердикт считается по фактам
независимо от лимита на длину отчёта.

`Clean` выдаётся только если проверено **всё**, что было в файле, и ни одно место
не читалось двусмысленно. Поэтому `Unverified` (а не `Clean`) получает файл, у которого
есть шифрованная или не разобранная часть; превышен лимит; два читателя увидели бы разные
документы (второе имя части, два формата в одном пакете, поле с одним именем под разными
префиксами); есть полиглот, байты за концом контейнера (кроме нулевого заполнения) или
данные в архиве, на которые ничто не ссылается; записи OLE, на которые никто не ссылается;
скрытые имена; расхождение типа содержимого части с её ролью; XML с неизвестным корневым
элементом; поток PDF с неподдержанным фильтром; база Access, каталог которой не прочитался.
Роль части OOXML определяется сначала по типу содержимого, затем по связи и лишь потом по
имени, так что название файла не может заставить сканер пропустить текст документа.
Текстовые файлы, которые Windows или интерпретатор запускают сами (`.url`, `.scf`, `.iqy`,
`.theme`, `.wsf`, `.sct`, `.jnlp` и т. п.), под видом документа отклоняются (`Rejected`);
скрипты (VBS, JS, пакетные, PowerShell) получают находку и не бывают `Clean`.
Всё это покрыто тестами на созданных командой входах (`crates/arca-xray/src/tests/`).
Отдельный **полигон** (`tests/malware-test/`, `crates/arca-xray/src/tests/malware_lab/`) — пятьдесят
обезвреженных образцов известных атак (макросы-загрузчики, MSDT/Follina, DDE, NTLM-утечка, бомбы и
«закольцованные» контейнеры, шпионские скрипты PDF и др.): они **генерируются** тестами (в репозитории
нет ни одного рабочего вредоноса), для каждого записан ожидаемый отчёт, а в CI тот же набор
прогоняется через настоящий Wasm-гость в песочнице. Реальных вредоносных файлов в наборе нет.

### Стерильная копия в один тап

Для документов OOXML (`docx`, `xlsx`, `pptx`, …), Visio OOXML, OpenDocument (`odt`, `ods`, `odp`, `odg`) и PDF можно создать **очищенную копию**:
без макросов, внешних связей, ревизий, комментариев и метаданных. Для старых DOC/XLS/PPT и RTF
копия — не очистка, а пересборка в новый OOXML по тому, что показал просмотр, с потерей вёрстки;
ссылки в такой копии не остаются ссылками, их адреса дописаны видимым текстом в скобках. Копия
собирается заново, а затем **проверяется тем же рентгеном ещё раз**. Если в ней
осталось что-то опасное, Arca её не выдаст. Результат одинаков при каждом
запуске. Поделиться копией можно через системное меню.

Для картинок (`png`, `jpeg`, `gif`, `bmp`) копия — это **новый PNG, написанный из пикселей**: ни метаданных, ни
миниатюры, ни остальных кадров, ни байтов после конца картинки, ни структуры оригинала.

### Из чего состоит проект

| часть | роль |
|---|---|
| `arca-digest` | SHA-256 и CRC-32, без зависимостей |
| `arca-container` | безопасное чтение ZIP, OLE2, XML и баз Jet/ACE со всеми лимитами |
| `arca-abi` | «договор» между приложением и песочницей (версия ABI — 8): как передать файл и получить ответ |
| `arca-xray` | сам «рентген» и стерилизатор |
| `arca-image` | декодеры PNG/JPEG/GIF/BMP и запись PNG для стерильной копии картинки |
| `arca-preview` | безопасный просмотр: DOCX/DOC, XLSX/XLS, PPTX/PPT, ODF, Visio (VSDX, VSD), Access, RTF, PDF, MSG, текст/CSV → нейтральная модель «абзацы · таблицы · слайды» и рисунок страницы (PDF, слайды с диаграммами, листы, схемы Visio, схема связей Access) |
| `arca-guest-xray` | `arca-xray` и `arca-preview`, собранные в Wasm-модуль для песочницы |
| `arca-sandbox` | запуск Wasm-модулей: проверка подлинности, лимиты, отмена, дедлайн |
| `arca-engine` | безопасная прослойка между приложением и песочницей: лимиты по устройству, коды результата, JSON страницами |
| `arca-jni` | JNI-мост для Android: `libarca_jni.so` (единственный нативный код приложения) |
| `arca-ffi` | C-мост над `arca-engine` для клиента iOS (`libarca_ffi.a`, заголовок `include/arca.h`) |
| `arca-attribution` | указание создателей, форки и экран «О проекте» |
| `android/` | приложение для Android: Java без AndroidX и Gradle, пакет собирается `tools/android/build-apk.sh` |
| `app/` | клиент для iOS на Swift/SwiftUI (`ArcaKit`) поверх `arca-ffi`; сборка XCFramework автоматизирована в CI (`.github/workflows/ios.yml`) |

Хост песочницы **не разбирает документы**: форматы читает только гость внутри песочницы.
Вне песочницы остаются три небольших места на Safe Rust, и их стоит знать: хост читает
центральный каталог ZIP (подсказка бюджета и проверка имён частей стерильной копии), смотрит
первые байты картинки и декодирует ответ гостя wire-кодеком под лимитами. Для каждого есть
свои границы (см. [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) §4.5 и модель угроз), но
это уже «парсеры вне песочницы», а не «ни одного».

### Что уже сделано и что дальше

Готовы «ядро безопасности» (проверка и очистка), **безопасный просмотр** основных
форматов и **приложение для Android**. Дальше:

1. **Visio и Access.** Рисунок Visio (VSDX и бинарный VSD) рисуется: геометрия фигур, цвета и
   темы файла, коннекторы со стрелками, слои, мастера; текст и данные фигур — в просмотре (строки,
   которые вставил сам просмотр, помечены как синтетические). Приближённо: стрелки — простые
   треугольники, градиенты и тени темы не рисуются, 3D нет. Access открывается как таблицы со схемой
   (типы, размеры, ключи, обязательность), индексами и связями; сохранённые запросы — восстановленный
   SQL с пометкой «не проверено» (ничего не выполняется); схема связей раскладывает таблицы по связям
   (`1` — `∞`), линии идут по зазорам, не пересекая рамок.
2. **Рисование страниц** — сделано: PDF, слайды ODP/PPTX (в том числе картинки-заливки, фоны и
   диаграммы — столбцы, линии, области, круговые), листы ODS/XLSX/XLS, схемы Visio и схема связей
   Access (`crates/arca-preview/src/pdf`, `slide_draw`, `sheet_draw`, `visio_draw`). Дальше: диаграммы
   в листах и документах, точечные диаграммы, картинки в бинарном `.ppt`.
3. **iOS-клиент** на том же ядре (`app/`, `crates/arca-ffi`): кодовая база на Swift/SwiftUI
   написана, сборка XCFramework и тесты — в CI на macOS; **на реальном iPhone не запускался**,
   новые экраны 0.6.0 (темы, объяснение макросов, страницы) на Swift не собирались.
4. **Складные устройства** — сделано в коде (шарнир, поза, настольный режим), проверено на
   эмуляторе размеров окон; **на живом складном устройстве не проверялось**.
5. **Проверка на прочность:** расширенный фаззинг парсеров (`fuzz/`), детерминированные мутационные тесты картинок и Jet, сравнение с независимыми реализациями.
6. **Магазины приложений:** публикация в F-Droid и Google Play (и App Store для iOS) — запланирована.

Интерпретатор `wasmi` выбран вместо быстрых JIT-движков намеренно: iOS запрещает
сторонним приложениям исполнять сгенерированный код, а интерпретатор к тому же
проще аудировать.

### Поддержка и атрибуция

Arca бесплатна и без рекламы. Проект живёт на пожертвованиях, поэтому лицензия
(AGPL v3 с дополнительными условиями) требует, чтобы форки сохраняли указание
оригинальных создателей и ссылку на их поддержку на экране «О проекте». Свою
ссылку форк может добавить рядом (`fork_attribution.toml`).

## Что уже умеет ядро

- Определяет формат только по сигнатурам и отвергает zip-бомбы, Zip Slip,
  XXE, Billion Laughs, глубокую вложенность, полиглоты, расхождения парсеров
  и замаскированные исполняемые файлы.
- Находит и показывает как текст, ничего не исполняя: VBA (с исходниками),
  XLM / Excel 4.0, DDE (в том числе обфусцированный), OLE / ActiveX / пакеты,
  эксплойты Equation Editor, JavaScript и Launch в PDF, удалённые шаблоны,
  трекинг-пиксели, UNC-пути (утечки NTLM), `ms-msdt:` и т. п.
- Показывает криминалистические метаданные: автор, организация, компьютер,
  локальные пути, принтер, время правки, ревизии, комментарии.
- **Стерильная копия в один тап** (OOXML, Visio OOXML, OpenDocument, PDF): без макросов, внешних связей,
  ревизий, комментариев и метаданных, с повторной проверкой результата.
- **Картинки в параноидальном режиме:** PNG, JPEG, GIF, BMP (файлы и картинки внутри DOCX, PPTX, XLSX, ODF,
  RTF и PDF) раскодирует только наш безопасный Rust-декодер внутри песочницы, а не системный декодер Android;
  по умолчанию картинка показывается по тапу; GPS, серийные номера, миниатюры и данные после конца картинки
  сообщаются в «Рентгене»; байты, которые декодер не может объяснить (приватные блоки, хвосты потоков,
  зазоры), считаются отдельно (`unaccounted`), а проверка на полиглот идёт по всей картинке всегда.
  Стерильная копия картинки — новый PNG, написанный из пикселей и строго перечитанный
  ([docs/IMAGES.md](docs/IMAGES.md)).
- Не говорит «Чистый» о том, чего не проверил: зашифрованная или не
  разобранная часть даёт вердикт `Unverified`, а наводнение безобидными
  находками не может спрятать решающую.
- **Показывает содержимое документа** (Word, Excel, PowerPoint — в том числе
  старые `.doc`/`.xls`/`.ppt`, OpenDocument, RTF, PDF как текст, письма Outlook, текст и
  CSV, базы Access, рисунки Visio) — только чтение: ничего не исполняется, ссылки
  перечисляются, скрытое помечается. Любая обрезка, пропуск или приближение сопровождается
  уведомлением (молчаливых обрезок нет), строки, которые вставил сам просмотр (подпись
  соединения, имя фигуры без текста, SQL запроса), помечены как синтетические и отличаются
  от текста документа.
- Исполняет всё это внутри песочницы `wasmi` с лимитами памяти (пропорциональна
  файлу, около 96 МиБ для небольшого) и CPU-топлива (по умолчанию не больше 4·10¹¹, жёсткий
  потолок движка — фиксированные 10¹², его не поднять ни размером, ни содержимым файла); топливо
  выдаётся порциями, поэтому разбор можно отменить за миллисекунды и он ограничен по времени
  (`CancelToken`, дедлайн). Результат песочницы не больше 64 МиБ (40 МиБ для картинки), JSON для
  приложения — страницами по 8 МиБ, отчёт — до 32 МиБ. Модуль-гость закреплён по SHA-256
  (ожидаемый хэш вшит при сборке) и не имеет ни одного импорта. Пароли и буферы документов
  хранятся в `Zeroizing`, `Debug` не печатает содержимое — обнуление без гарантий для копий,
  которые могли остаться у аллокатора или зависимостей.

## Сборка

```sh
cargo test --workspace
bash tools/build-guest.sh        # = cargo build -p arca-guest-xray --target wasm32-unknown-unknown --profile guest
# сквозные тесты гостя в песочнице (в release: интерпретатор в разы быстрее)
ARCA_GUEST_XRAY_WASM=$PWD/target/wasm32-unknown-unknown/guest/arca_guest_xray.wasm \
ARCA_CORPUS_DIR=$PWD/tests/fixtures \
    cargo test --release -p arca-guest-xray --test e2e_sandbox   # путь к корпусу — абсолютный
cargo run -p arca-xray --example xray -- scan file.docx
# фаззинг: ARCA_FUZZ_ITERS=30000 cargo test --release -p arca-xray mutation_fuzz,
# libFuzzer — см. fuzz/README.md
```

Rust-часть (все крейты, кроме `arca-ffi` для iOS) собирается и тестируется на любом Linux; на
Windows удобнее всего WSL с Ubuntu. Нужно (в каталоге проекта внутри Linux, а не в `/mnt/c`, иначе сборка
очень медленная):

```sh
sudo apt install build-essential zip unzip curl git     # build-essential — только как линкер: C-код не собирается
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh   # затем перезапустить оболочку
rustup toolchain install                                        # версия и цели — из rust-toolchain.toml (1.97.0, wasm32, Android)
```

Для APK дополнительно нужны JDK 17+, Android SDK (`platforms;android-36`, `build-tools;36.0.0`) и NDK
(только компоновщик). Для локальной сборки пакета подойдёт одноразовый ключ (`ARCA_THROWAWAY_KEY=1`);
релизным ключом подписывает только CI, см. [`docs/RELEASING.md`](docs/RELEASING.md). Эти шаги собраны по
скриптам репозитория; на чистой машине как последовательность целиком они в рамках проверки 0.2.2 не прогонялись.

Android-приложение (нужны Android SDK и NDK-компоновщик; подробно — в
[`docs/ANDROID.md`](docs/ANDROID.md)):

```sh
bash tools/build-guest.sh                       # Wasm-гость
bash tools/android/check-android.sh             # ресурсы, манифест, компиляция против API 26 и 36, тесты
ARCA_GUEST_WASM=$PWD/target/wasm32-unknown-unknown/guest/arca_guest_xray.wasm \
    ARCA_CORPUS_DIR=$PWD/tests/fixtures bash android/host-test/run.sh   # JNI на JVM с -Xcheck:jni
# пакет и релиз собирает CI: .github/workflows/android.yml, порядок выпуска — docs/RELEASING.md
```

Клиент iOS (`app/`) собирается в окружении macOS: `bash tools/ios/check-ios.sh` (XCFramework из `arca-ffi`,
проверка запретных импортов, `swift build`, `swift test`; автоматизировано в `.github/workflows/ios.yml` на
`macos-14`).

Подробности: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md),
