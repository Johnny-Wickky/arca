# Архитектурное руководство и детальный анализ iOS-версии Arca

> **Статус документа.** Архитектурная спецификация нативного iOS-клиента Arca (ArcaKit). Документ описывает
> структуру Swift-пакета (`app/`), C-ABI мост (`crates/arca-ffi`), модель изоляции WebAssembly-песочницы,
> пользовательский интерфейс SwiftUI и план интеграции платформенных расширений. Сборка и прогон тестов
> выполняются в среде macOS (Xcode 15+, Swift 5.9+) через `tools/ios/check-ios.sh` и CI (`.github/workflows/ios.yml`).

Настоящий документ представляет собой исчерпывающий архитектурный, системный и инженерный анализ
создания клиента **Arca для экосистемы Apple iOS / iPadOS**. Документ подробно раскрывает все уровни
системы — от низкоуровневого взаимодействия с ядром на языке Rust и песочницей WebAssembly (`wasmi`)
через C-ABI до многопоточной среды Swift Concurrency, декларативного интерфейса SwiftUI, расширений
системы (Share Extension, WidgetKit), локальных уведомлений и криптографического хранилища «Паспорта
Защитника» с аппаратной изоляцией Secure Enclave.

Документ содержит 16 специализированных ASCII-диаграмм, всесторонний разбор плюсов, минусов, нюансов,
компромиссов реализации и руководство по проверке соответствия требованиям безопасности App Store Review.

## 1. Фундаментальные принципы и инварианты Arca iOS

iOS-клиент Arca проектируется под бескомпромиссную модель нулевого доверия (Zero-Trust).
Любой входящий файл считается враждебным эксплойтом, нацеленным на компрометацию адресного
пространства устройства, кражу биометрических данных или эскалацию привилегий в iOS.

```text
+-----------------------------------------------------------------------------------------+
|                                    ИНВАРИАНТЫ ARCA IOS                                  |
+-----------------------------------------------------------------------------------------+
| 1. ZERO-NETWORK        | Никаких сетевых вызовов (CFNetwork, URLSession, BSD sockets).  |
|                        | Никаких трекеров, телеметрии, аналитики и сетевых SDK.         |
| 2. WASM ISOLATION      | Парсинг документов только внутри интерпретатора wasmi.         |
|                        | Без JIT-компиляции (полная совместимость с W^X политикой iOS). |
| 3. OPAQUE HANDLES      | Swift оперирует int64_t handle. Нулевой доступ к сырым полям   |
|                        | внутренних структур ядра Rust.                                 |
| 4. STRICT ZEROIZATION  | Все нативные буферы результатов затираются нулями (zeroize)   |
|                        | в момент освобождения перед вызовом системного free().         |
| 5. OWN ICONOGRAPHY     | Никаких системных SF Symbols или Google Material Icons.        |
|                        | 100% авторские векторные BezierPath глифы (Правило 6).          |
| 6. AGPLv3 SEC. 7(b)    | Неустранимый приоритетный показ создателей оригинального ядра  |
|                        | (команда Pharos) и неизменяемый локальный Паспорт Защитника.   |
+-----------------------------------------------------------------------------------------+
```

### Архитектурные требования:
* **Запрет JIT и политика Apple W^X (Write XOR Execute):** iOS запрещает динамическое выделение
  исполняемых страниц памяти сторонними приложениями (за исключением специального entitlement в
  отладчике или Safari Nitro). Поэтому ядро Arca использует интерпретатор WebAssembly `wasmi`,
  работающий исключительно в режиме программного исполнения байткода. Это гарантирует отсутствие
  необходимости в W^X исключениях и 100% соответствие Apple App Store Review Guideline 2.5.2.
* **Детерминированное освобождение ресурсов:** Приложение не удерживает открытые файловые
  дескрипторы дольше, чем необходимо для загрузки данных в память ядра. Вся нативная память,
  содержащая расшифрованный или распарсенный контент, зачищается криптографически стойким
  затиранием памяти (`zeroize`).
* **Независимость от инфраструктуры сторонних поставщиков:** Приложение не имеет зависимостей
  от CocoaPods, Carthage или сторонних бинарных пакетов. Единственные внешние компоненты —
  собственное статическое ядро `libarca_ffi.a` и Swift-пакет `ArcaKit` с исходным кодом
  непосредственно в репозитории.

## 2. Глобальная архитектура системы и границы изоляции

Архитектура Arca для iOS разделена на пять строго разграниченных слоев с однонаправленным
потоком управления:

```text
+-----------------------------------------------------------------------------------------+
| СХЕМА 1: ГЛОБАЛЬНАЯ МНОГОУРОВНЕВАЯ АРХИТЕКТУРА И ГРАНИЦЫ ИЗОЛЯЦИИ В IOS                |
+-----------------------------------------------------------------------------------------+

  [ ПОЛЬЗОВАТЕЛЬСКИЙ СЛОЙ: ДЕКЛАРАТИВНЫЙ ИНТЕРФЕЙС SWIFTUI ]
  +-------------------------------------------------------------------------------------+
  | Views: DocumentViewer, XRayReportView, ImageViewer, SanitizeSheet, AboutPassportView|
  | State: AppState (@ObservableObject / Swift Observation), Dynamic Locale Dispatcher   |
  | Design System: 6 Themes, Critically Damped Springs, Pure Bezier Path Glyphs         |
  +-------------------------------------------------------------------------------------+
                                            │
                                            ▼  Swift Structured Concurrency (async/await)
  [ СЕРВИСНЫЙ СЛОЙ: SWIFT SDK (ArcaKit) ]   │
  +-------------------------------------------------------------------------------------+
  | actor ArcaEngine: изоляция состояния, сериализация задач, Task Priority             |
  | ArcaHaptics: CoreHaptics тактильный отклик (Rich transient / continuous patterns)   |
  | PatronStore: локальная БД статистики с шифрованием .completeFileProtection          |
  +-------------------------------------------------------------------------------------+
                                            │
                                            ▼  Clang Module Import (ArcaCore.h)
  [ СВЯЗУЮЩИЙ СЛОЙ: C-ABI МОСТ (crates/arca-ffi) ]
  +-------------------------------------------------------------------------------------+
  | include/arca.h: C99 заголовки, int64_t handle, ArcaBuffer, ArcaEngineConfig        |
  | src/ffi.rs: Единственная точка с unsafe-кодом, верифицированная tools/check-unsafe  |
  | Zeroize Memory Manager: криптографическое затирание буферов перед деаллокацией      |
  +-------------------------------------------------------------------------------------+
                                            │
                                            ▼  Rust Static Linking (libarca_ffi.a)
  [ СЛОЙ ЯДРА: RUST ZERO-TRUST ENGINE (crates/arca-engine) ]
  +-------------------------------------------------------------------------------------+
  | Управление сессиями документов, планировщик задач, контроль таймаутов и памяти      |
  | Ограничение CPU Fuel (лимит инструкций Wasm) и Memory Ceiling (жесткий лимит RAM)   |
  +-------------------------------------------------------------------------------------+
                                            │
                                            ▼  Ephemeral Sandbox Guest Instantiation
  [ СЛОЙ ИЗОЛЯЦИИ: ОДНОРАЗОВАЯ ПЕСОЧНИЦА WASM (crates/arca-sandbox via wasmi) ]
  +-------------------------------------------------------------------------------------+
  | Wasm Guest: arca_guest.wasm (вкомпилирован через include_bytes!)                    |
  | 0 системных импортов, 0 возможностей ввода-вывода (no syscalls, no network, no fs) |
  | Модули: Рентген-анализатор, Санитизатор (Стерилизатор), Безопасный Растеризатор     |
  +-------------------------------------------------------------------------------------+
```

### Пояснения к слоям:
1. **SwiftUI Host Layer:** Работает на главном потоке (`@MainActor`). Отвечает исключительно
   за рендеринг примитивов, обработку пользовательских жестов и анимаций. Не содержит бизнес-логики
   парсинга документов.
2. **ArcaKit Actor Layer:** Изолирует состояние движка в акторе `ArcaEngine`. Любые вызовы к FFI
   выполняются на фоновом пуле потоков через `Task.detached`, предотвращая блокировку UI.
3. **C-ABI Bridge (`ArcaCore`):** Стандартизированный C99 интерфейс без исключений и C++ RTTI.
   Обеспечивает строгое сопоставление типов Swift <-> C <-> Rust.
4. **Rust Core Layer (`arca-engine`):** Управляет пулом сессий документов. Документ представлен
   целочисленным дескриптором `int64_t`. Любой невалидный или просроченный дескриптор возвращает
   `ARCA_STATUS_BAD_HANDLE` (-10) без сбоев памяти.
5. **Wasm Sandbox (`wasmi`):** Одноразовая виртуальная машина. Для каждого документа создается
   изолированный инстанс с выделенным бюджетом памяти (например, 64–256 МБ) и лимитом инструкций (Fuel).
   В случае эксплойта внутри документа (попытка переполнения буфера или бесконечного цикла), падает
   только инстанс Wasm-гостя, а хост-процесс iOS продолжает стабильную работу.

## 3. Модель угроз iOS и конвейер инжестии враждебных файлов

Инжестия файлов на iOS существенно отличается от Android и desktop-систем наличием жесткого
механизма **App Sandbox**, контейнеризации и системы **Security-Scoped URL**.

```text
+-----------------------------------------------------------------------------------------+
| СХЕМА 2: КОНВЕЙЕР ИНЖЕСТИИ ВРАЖДЕБНЫХ ФАЙЛОВ И ГРАНИЦЫ SECURITY-SCOPED РЕСУРСОВ         |
+-----------------------------------------------------------------------------------------+

  ВХОДЯЩИЕ ИСТОЧНИКИ:
  [UIDocumentPicker]       [Share Extension]         [Drag & Drop]         [Files.app / AirDrop]
         │                         │                       │                         │
         ▼                         ▼                       ▼                         ▼
  +──────────────────────────────────────────────────────────────────────────────────+
  |              ЭТАП 1: ПОЛУЧЕНИЕ SECURITY-SCOPED URL (iOS Host Sandbox)            |
  |              let isAccessing = url.startAccessingSecurityScopedResource()        |
  +──────────────────────────────────────────────────────────────────────────────────+
                                            │
                                            ▼
  +──────────────────────────────────────────────────────────────────────────────────+
  |              ЭТАП 2: БЕЗОПАСНЫЙ ЗАХВАТ ДЕСКРИПТОРА ФАЙЛА (Low-Level POSIX)       |
  |              let fd = open(url.path, O_RDONLY | O_CLOEXEC | O_NOFOLLOW)          |
  |              defer {                                                             |
  |                  close(fd)                                                       |
  |                  url.stopAccessingSecurityScopedResource()                       |
  |              }                                                                   |
  +──────────────────────────────────────────────────────────────────────────────────+
                                            │
                                            ▼  arca_open_fd(engine, fd, &handle)
  +──────────────────────────────────────────────────────────────────────────────────+
  |              ЭТАП 3: ЧТЕНИЕ И СТРИМИНГ В ПАМЯТЬ ЯДРА RUST                        |
  |  - Валидация размера (ARCA_STATUS_TOO_LARGE при превышении лимита)               |
  |  - Определение Magic Bytes (распознавание формата без доверия к расширению)      |
  |  - Аллокация строго ограниченного буфера в куче ядра Rust                        |
  +──────────────────────────────────────────────────────────────────────────────────+
                                            │
                                            ▼  arca_run(engine, job, ...)
  +──────────────────────────────────────────────────────────────────────────────────+
  |              ЭТАП 4: ИЗОЛИРОВАННАЯ ЭКСПЕРТИЗА В ПЕСОЧНИЦЕ WASM                   |
  |  - Декомпрессия контейнеров (Zip, OLE, Compound) с лимитом сжатия (Anti-Zip-Bomb)|
  |  - Поиск макросов VBA, формул XLM 4.0, DDE, OLE объектов, скрытых веб-трекеров   |
  |  - Генерация вердикта ArcaVerdict (CLEAN / WARNING / DANGER / UNTRUSTED)         |
  +──────────────────────────────────────────────────────────────────────────────────+
                                            │
                                            ▼  arca_report_get_json(engine, handle, &buf)
  +──────────────────────────────────────────────────────────────────────────────────+
  |              ЭТАП 5: БЕЗОПАСНАЯ ПЕРЕДАЧА СТРУКТУРИРОВАННОГО ОТЧЕТА В SWIFT        |
  |  - Возврат легковесного UTF-8 JSON через ArcaBuffer                              |
  |  - Парсинг в Swift-структуру ArcaReport (Decodable)                              |
  |  - Вызов arca_buffer_free(...) с криптографическим затиранием zeroize            |
  +──────────────────────────────────────────────────────────────────────────────────+
```

### Нюансы и защитные меры на этапе инжестии:
1. **Флаг `O_NOFOLLOW`:** Предотвращает атаки типа Symlink Traversal, если файл поступает из
   общей директории или сетевого шара.
2. **Автоматический баланс ресурсов `startAccessingSecurityScopedResource`:** Приложение гарантирует
   строгий вызов `stopAccessingSecurityScopedResource()` в блоке `defer`. Утечка вызовов
   доступа к security-scoped ресурсам приводит к исчерпанию лимита дескрипторов ядра iOS
   и завершению процесса операционной системой.
3. **Отказ от расширений файлов:** Тип документа (`DocType`) никогда не определяется по его имени.
   Входной буфер анализируется по сигнатурам заголовков (Magic Bytes) непосредственно ядром.

## 4. C-ABI мост, дескрипторы и жизненный цикл памяти

C-ABI мост (`crates/arca-ffi`) служит непреодолимым барьером безопасности между Swift и Rust.
Все объекты в Swift представлены исключительно непрозрачными дескрипторами `int64_t`.

```text
+-----------------------------------------------------------------------------------------+
| СХЕМА 3: ЖИЗНЕННЫЙ ЦИКЛ ПАМЯТИ, НЕПРОЗРАЧНЫЕ ДЕСКРИПТОРЫ И ПРОТОКОЛ ZEROIZE            |
+-----------------------------------------------------------------------------------------+

  SWIFT RUNTIME (ARC Managed Heap)                    RUST NATIVE RUNTIME (Jemalloc/System)
  +──────────────────────────────+                    +───────────────────────────────────+
  | let engine = ArcaEngine()    |                    | struct EngineInner {              |
  | let handle: Int64 = 1042     |                    |   sessions: BTreeMap<i64, Session>|
  +──────────────────────────────+                    +───────────────────────────────────+
                 │                                                      │
                 │ arca_report_get_json(engine, handle, &rawBuffer)     │
                 ├─────────────────────────────────────────────────────►│ 1. Аллокация буфера
                 │                                                      │    в куче Rust:
                 │                                                      │    vec![0u8; len]
                 │                                                      │ 2. Сериализация JSON
                 │                                                      │    в выделенный буфер
                 │◄─────────────────────────────────────────────────────┤
                 │ Возврат структуры ArcaBuffer:                        │
                 │ { ptr: 0x10842000, len: 4096, capacity: 4096 }       │
  +──────────────┴───────────────+                                      │
  | 3. Создание Swift Data:      |                                      │
  |    Data(bytes: ptr, count)   |                                      │
  |    (копирование в безопасную |                                      │
  |     память Swift)            |                                      │
  +──────────────┬───────────────+                                      │
                 │                                                      │
                 │ arca_buffer_free(&rawBuffer)                         │
                 ├─────────────────────────────────────────────────────►│ 4. zeroize_slice(ptr)
                 │                                                      │    [0x00, 0x00, ...]
                 │                                                      │ 5. Освобождение кучи:
                 │                                                      │    dealloc(ptr)
                 │◄─────────────────────────────────────────────────────┤
                 │ Буфер обнулен и освобожден                           │
```

### ABI-контракт структур данных (`include/arca.h`):

```c
typedef struct ArcaBuffer {
    uint8_t *ptr;         /* Указатель на сырой буфер памяти в куче Rust */
    size_t len;           /* Длина полезной нагрузки в байтах */
    size_t capacity;      /* Полная емкость выделенного буфера */
} ArcaBuffer;

typedef struct ArcaEngineConfig {
    size_t max_input_bytes;   /* Жесткий лимит размера файла (по умолч. 256 МБ) */
    size_t max_output_bytes;  /* Лимит стерилизованного вывода */
    size_t guest_memory_pages;/* Лимит страниц Wasm-памяти (1 страница = 64 КиБ) */
    uint64_t guest_fuel_limit;/* Лимит инструкций Wasm (защита от DoS) */
    uint32_t timeout_ms;      /* Таймаут исполнения (по умолч. 10 000 мс) */
    uint32_t flags;           /* Флаги конфигурации */
} ArcaEngineConfig;
```

### Спецификация дескрипторов (Handles over Pointers):
* Значение дескриптора — строго положительное монотонно возрастающее 64-битное целое число (`> 0`).
* Отрицательное значение указывает на системный код ошибки (например, `-ARCA_STATUS_BAD_HANDLE`).
* Освобожденный дескриптор немедленно удаляется из реестра активных сессий Rust. Повторное
  обращение по освобожденному идентификатору исключает Use-After-Free (UAF) и возвращает ошибку.

## 5. Swift Concurrency, Actor-модель и мгновенная отмена задач

В архитектуре iOS-приложения недопустимы любые подвисания UI или блокировки главного потока.
Ядро Arca предоставляет механизм потокобезопасной отмены вычислений через атомарные токены.

```text
+-----------------------------------------------------------------------------------------+
| СХЕМА 4: АСИНХРОННАЯ МОДЕЛЬ SWIFT CONCURRENCY И ПОТОКОБЕЗОПАСНАЯ ОТМЕНА ЗАДАЧ          |
+-----------------------------------------------------------------------------------------+

  UI MAIN THREAD (@MainActor)                         BACKGROUND WORKER POOL (Task.detached)
  +─────────────────────────+                         +─────────────────────────────────────+
  | Пользователь нажал      |                         | let job = arca_job_create(engine)  |
  | кнопку "Отмена"         |                         | let cancelToken =                   |
  +─────────────────────────+                         |   arca_job_get_cancellation_token() |
               │                                      +─────────────────────────────────────+
               │                                                         │
               │                                                         │ Вызов arca_run(...)
               │                                                         ▼
               │                                      +─────────────────────────────────────+
               │                                      | ЯДРО RUST: Исполнение цикла Wasm    |
               │                                      | while step() {                      |
               │                                      |   if cancel_flag.load(Relaxed) {    |
               │                                      |       return STATUS_CANCELLED;      |
               │                                      |   }                                 |
               │                                      | }                                   |
               │                                      +─────────────────────────────────────+
               │                                                         ▲
               │ Task.detached(priority: .userInitiated)                 │
               │ arca_job_cancel(engine, jobHandle)                      │
               └─────────────────────────────────────────────────────────┘
                 Атомарная запись AtomicBool: true (мгновенное прерывание)
```

### Реализация `actor ArcaEngine`:
Актор Swift гарантирует, что состояние движка изолировано от состояния представлений SwiftUI.
Код актора оборачивает работу с FFI в асинхронные структуры с автоматической регистрацией
обработчика отмены:

```swift
public actor ArcaEngine {
    private var enginePtr: OpaquePointer?

    public func analyze(document handle: Int64) async throws -> ArcaReport {
        let jobHandle = try createJob()
        return try await withTaskCancellationHandler {
            try await runJob(jobHandle: jobHandle)
        } onCancel: {
            // Мгновенный вызов из любого потока, безопасный для C-ABI
            arca_job_cancel(self.enginePtr, jobHandle)
        }
    }
}
```

## 6. Виртуализированный движок отображения документов

Отображение объемных документов (таблицы Excel на миллион строк, презентации на 500 слайдов,
многостраничные отчеты Word) на мобильных устройствах сталкивается с жесткими ограничениями памяти
(Jetsam в iOS жестко убивает приложения, превышающие допустимый порог памяти).
Arca решает эту задачу с помощью потоковой виртуализации и пагинации чанками по 64 элемента.

```text
+-----------------------------------------------------------------------------------------+
| СХЕМА 5: ПОТОКОВАЯ ВИРТУАЛИЗАЦИЯ И ЛЕНИВАЯ ПОДГРУЗКА ЭЛЕМЕНТОВ ДОКУМЕНТА                |
+-----------------------------------------------------------------------------------------+

  ВИДИМАЯ ОБЛАСТЬ ЭКРАНА (Viewport)
  +────────────────────────────────────────────────────────+
  | Строка 124: Итоговая выручка за Q3       14,520,000 $  |  ЧАНК N (В памяти SwiftUI)
  | Строка 125: Операционные расходы        -8,140,000 $  |  (Элементы 120...184)
  | Строка 126: Налоговые отчисления        -1,200,000 $  |  Размер в памяти: ~16 Кб
  +────────────────────────────────────────────────────────+
               ▲                                ▲
               │ Скролл вверх                   │ Скролл вниз
  +────────────┴───────────+       +────────────┴───────────+
  | ЧАНК N-1 (Кэш упреждения|       | ЧАНК N+1 (Кэш упреждения|
  | Элементы 64...119      |       | Элементы 185...248     |
  +────────────────────────+       +────────────────────────+
               │                                │
  =============▼================================▼==========================================
  ГРАНИЦА C-ABI (Lazy Fetching on Demand)
  arca_preview_get_slice(engine, docHandle, offset: 185, count: 64, &buffer)
  =========================================================================================
               │
               ▼
  [ RUST CORE: ВНУТРЕННИЙ БИНАРНЫЙ ИНДЕКС ДОКУМЕНТА ]
  Быстрый jump по смещениям строк без повторного разбора всего XML-дерева документа
```

### Особенности виртуализации:
1. **Spreadsheet Grid Virtualization:** Таблицы отрисовываются через виртуализированные
   `LazyVStack` и `LazyHStack` с двумерным индексом ячеек `(Row, Column)`. Данные ячеек
   запрашиваются только для видимого диапазона плюс 1 экран запаса (Prefetch Buffer).
2. **Text Reflow & Sanity Clamping:** Текст абзацев проходит предварительную очистку от
   скрытых символов форматирования и атак типа BiDi Override (символы разворота направления
   текста, используемые для маскировки расширений и фишинга).
3. **Отсутствие системного WebView:** Документы никогда не конвертируются в HTML/DOM и не
   отрисовываются через `WKWebView`. Рендеринг через WebKit несет колоссальную поверхность
   атаки (JIT-эксплойты движка JavaScriptCore, уязвимости парсинга CSS). Вся верстка в Arca
   строится исключительно на нативных примитивах SwiftUI `Text`, `Grid` и `Canvas`.

## 7. Изолированный конвейер растровой графики и EXIF-криминалистика

Системные декодеры изображений (ImageIO, CoreGraphics) исторически являются источником критических
уязвимостей нулевого дня (например, эксплойты BLASTPASS и FORCEDENTRY в декодерах WebP, JPEG и TIFF).
Arca полностью изолирует обработку любых изображений внутри Wasm-песочницы.

```text
+-----------------------------------------------------------------------------------------+
| СХЕМА 6: БЕЗОПАСНЫЙ РАСТРОВЫЙ КОНВЕЙЕР И ЭКСПЕРТИЗА МЕТАДАННЫХ (EXIF FORENSICS)         |
+-----------------------------------------------------------------------------------------+

  ВХОДЯЩИЙ ФАЙЛ ИЗОБРАЖЕНИЯ (JPEG / PNG / BMP / WebP / TIFF)
                              │
                              ▼
  +───────────────────────────────────────────────────────────────────────────────────────+
  | WASM SANDBOX: ИЗОЛИРОВАННЫЙ ДЕКОДЕР И СТЕРИЛИЗАТОР ИЗОБРАЖЕНИЙ                        |
  | 1. Парсинг структуры файла без системных кодеков iOS (Pure Rust: image, jpeg-decoder) |
  | 2. Защита от декомпрессионных бомб (Pixel Flood Attack / Giga-pixel decompression)    |
  | 3. Извлечение и валидация EXIF, GPS, IPTC, XMP метаданных                             |
  | 4. Декодирование в сырой массив пикселей: RGBA_8888 (Raw Framebuffer)                 |
  +───────────────────────────────────────────────────────────────────────────────────────+
                 │                                                   │
                 ▼ Raw RGBA Pixels (Wasm Memory)                     ▼ JSON Metadata
  +─────────────────────────────────────────────+    +────────────────────────────────────+
  | РЕКОНСТРУКЦИЯ КАДРА В БЕЗОПАСНОЙ ПАМЯТИ     |    | КРИМИНАЛИСТИЧЕСКИЙ ОТЧЕТ           |

  | - Создание CGDataProvider                   |    |   о геолокационной утечке)         |
  | - Инициализация CGImage / UIImage           |    | - Серийный номер камеры, объектив  |

```

### Защита от пиксельных бомб (Pixel Flood Mitigation):
* Максимальный размер декодируемого растра ограничен 4 мегапикселями (2048x2048) в стандартном
  режиме просмотра и 16 мегапикселями при явном запросе пользователя («С полным качеством»).
* Попытка передать изображение со сжатым заголовком, обещающим развертывание в гигабайты памяти
  (например, 100 000 x 100 000 пикселей), немедленно прерывается со статусом `ARCA_STATUS_RESOURCE_LIMIT`.

## 9. Паспорт Защитника и аппаратное шифрование данных

В соответствии с требованиями лицензии **AGPLv3 (Раздел 7b)** и моделью полной автономности,
в приложении реализован «Паспорт Защитника» (Patron Passport). Паспорт хранит локальную
статистику обезвреженных угроз без отправки на сервер и защищает ее аппаратным шифрованием.

Начиная с 0.3.0 числа считает общее ядро (Rust), а не Swift: `arca_stats_*` в `include/arca.h`
ведут кольцо из 400 дневных корзин и итог «за всё время» в одном непрозрачном блобе с версией и
CRC-32 (приложение хранит только его, под `.completeFileProtection`; номер дня — по локальному
календарю, часов в ядре нет), а `arca_reminder_*` решают, когда и можно ли показать напоминание о
поддержке (окно 11:00–20:30, интервал 7–9 дней, не чаще раза в 6 дней) и какой текст взять.
Тонкие обёртки лежат в `app/Sources/ArcaKit/Stats.swift` (`ArcaStats`, `ArcaReminderRules`); на
iOS остаётся только поставить локальное уведомление и опубликовать его. Старая запись паспорта из
36 байт переносится в блоб один раз через `arca_stats_fold_legacy`. Сборка Swift-компонентов
валидируется в окружении macOS CI (`ios.yml`).

```text
+-----------------------------------------------------------------------------------------+
```

## 12. Локальные уведомления и фоновая обработка

В отличие от стандартных приложений, использующих облачные Push-уведомления (Apple Push
Notification service, APNs), Arca полностью изолирована от сети. Все уведомления являются
**строго локальными** (`UNUserNotificationCenter`).

```text
+-----------------------------------------------------------------------------------------+
| СХЕМА 11: АРХИТЕКТУРА ЛОКАЛЬНЫХ УВЕДОМЛЕНИЙ ПРИ ДЛИТЕЛЬНОЙ ПАКЕТНОЙ ОБРАБОТКЕ           |
+-----------------------------------------------------------------------------------------+

  ОСНОВНОЙ ПРОЦЕСС ARCA (Пакетная стерилизация папки документов / Фоновая задача)
                           │
                           ▼
  +───────────────────────────────────────────────────────────────────────────────────────+
  | BGProcessingTask / BackgroundTasks Framework                                          |
  | Задача регистрируется в iOS Background Scheduler:                                     |
  | BGTaskScheduler.shared.register(forTaskWithIdentifier: "org.arca.batch", ...)         |
  +───────────────────────────────────────────────────────────────────────────────────────+
                           │
                           ▼ Выполнение в фоновом цикле
  +───────────────────────────────────────────────────────────────────────────────────────+
  | ПОСЛЕДОВАТЕЛЬНЫЙ РЕНТГЕН И СТЕРИЛИЗАЦИЯ ПАЧКИ ФАЙЛОВ В КУЧЕ RUST                      |
  | Документ 1/15 -> OK; Документ 2/15 -> УГРОЗА ОБЕЗВРЕЖЕНА; ...                         |
  +───────────────────────────────────────────────────────────────────────────────────────+
                           │
                           ▼ Завершение задачи
  +───────────────────────────────────────────────────────────────────────────────────────+
  | ФОРМИРОВАНИЕ ЛОКАЛЬНОГО УВЕДОМЛЕНИЯ (БЕЗ СЕРВЕРОВ И ТОКЕНОВ APNS)                     |
  | let content = UNMutableNotificationContent()                                          |
  | content.title = "Пакетная стерилизация завершена"                                     |
  | content.body = "Обработано файлов: 15. Устранено макросов и трекеров: 4."             |
  | let request = UNNotificationRequest(identifier: UUID().uuidString, content, trigger)  |
  | UNUserNotificationCenter.current().add(request)                                       |
  +───────────────────────────────────────────────────────────────────────────────────────+
```

### Преимущества локального подхода:
* **100% приватность:** На устройства Apple никогда не передается Device Push Token. Ни Apple,
  ни разработчики приложения не знают, когда, сколько и какие документы были проверены пользователем.
* **Работа без интернета (Air-Gapped Mode):** Уведомления надежно срабатывают даже на устройствах,
  находящихся в авиарежиме или в защищенных контурах безопасности без доступа к глобальной сети.

## 16. Кросс-компиляция, XCFramework и CI/CD

Бинарное ядро Arca упаковывается в современный формат **XCFramework**, поддерживающий как
физические 64-битные ARM-устройства, так и симуляторы iOS (включая архитектуры Apple Silicon и Intel).

```text
+-----------------------------------------------------------------------------------------+
| СХЕМА 15: ТОПОЛОГИЯ МУЛЬТИ-АРХИТЕКТУРНОЙ СБОРКИ И УПАКОВКИ XCFRAMEWORK                  |
+-----------------------------------------------------------------------------------------+

  RUST TOOLCHAIN (cargo build --target ...)
  +───────────────────────────────+      +────────────────────────────────────────────────+
  | aarch64-apple-ios             |      | aarch64-apple-ios-sim   | x86_64-apple-ios-sim |
  | (Физические iPhone и iPad)    |      | (Симулятор Apple Silic) | (Симулятор Intel Mac)|
  +───────────────────────────────+      +────────────────────────────────────────────────+
                 │                                        │
                 ▼                                        ▼ lipo -create
  +───────────────────────────────+      +────────────────────────────────────────────────+
  | libarca_ffi.a (Device slice)  |      | libarca_ffi.a (Fat Simulator Universal slice)  |
  +───────────────────────────────+      +────────────────────────────────────────────────+
                 │                                        │
                 └───────────────────┬────────────────────┘
                                     │
                                     ▼ xcodebuild -create-xcframework
  +───────────────────────────────────────────────────────────────────────────────────────+
  | ArcaCore.xcframework                                                                  |
  | ├── ios-arm64/                                (Срез для физических устройств)         |
  | │   └── libarca_ffi.a                                                                 |
  | ├── ios-arm64_x86_64-simulator/               (Универсальный срез для симуляторов)    |
  | │   └── libarca_ffi.a                                                                 |
  | └── Headers/                                  (C-ABI интерфейс)                       |
  |     ├── arca.h                                                                        |
  |     └── module.modulemap                                                              |
  +───────────────────────────────────────────────────────────────────────────────────────+
```

### Архитектура скриптов автоматизации:
* `tools/ios/build-xcframework.sh` автоматизирует кросс-компиляцию для всех целевых платформ,
  проверяет выравнивание памяти и генерирует итоговый `ArcaCore.xcframework`.
* `tools/ios/check-ios.sh` производит статический аудит кода:
  1. Запрет вызовов небезопасных сетевых API (`URLSession`, `CFNetwork`).
  2. Валидация политики безопасности unsafe-блоков (`tools/check-unsafe.sh`).
  3. Проверка отсутствия упоминаний SF Symbols в исходном коде.

## 17. Детальный сравнительный анализ: Плюсы, Минусы и Компромиссы

В таблице ниже приведен глубокий технический анализ выбора нативного стека (SwiftUI + Rust FFI)
по сравнению с альтернативными кроссплатформенными решениями (Flutter, React Native, Pure UIKit).

```text
+-----------------------------------------------------------------------------------------+
| СХЕМА 16: ДЕТАЛЬНАЯ МАТРИЦА СРАВНЕНИЯ АРХИТЕКТУРНЫХ ПОДХОДОВ ДЛЯ ARCA IOS               |
+-----------------------------------------------------------------------------------------+

АРХИТЕКТУРНЫЙ КРИТЕРИЙ     NATIVE SWIFTUI + RUST (ВЫБРАНО)  FLUTTER / REACT NATIVE       PURE UIKIT (LEGACY)
──────────────────────────────────────────────────────────────────────────────────────────
1. Поверхность атаки       МИНИМАЛЬНАЯ                      ОГРОМНАЯ                     НИЗКАЯ
   цепочки поставок        (0 сторонних пакетов)            (Движок Dart VM / V8, Skia)  (Требует ручного управления)

2. Соответствие правилу    ПОЛНОЕ                           ЗАТРУДНЕНО                   ПОЛНОЕ
   Apple W^X (No JIT)      (wasmi интерпретатор)            (Требуется AOT Dart)         (Нативный компилируемый код)

3. Доступ к дескрипторам   ПРЯМОЙ POSIX                     ЧЕРЕЗ МОСТ (METHOD CHANNEL)  ПРЯМОЙ POSIX
   (open/close/mmap)       (Без сериализации данных)        (Накладные расходы, копии)   (Без сериализации данных)

   (App Store IPA Size)    (Ядро Rust + Wasm байткод)       (Движок + рантайм + шрифты)  (Только системные dylib)

5. Поддержка Share &       НАТИВНАЯ                         ПРОБЛЕМАТИЧНАЯ               НАТИВНАЯ
   WidgetKit Extensions    (Общий Swift-пакет ArcaKit)      (Большой вес в лимите 30МБ!) (Полная поддержка)

6. Расход оперативной      ЭТАЛОННЫЙ                        ВЫСОКИЙ                      ЭТАЛОННЫЙ
   памяти в фоне           (Детерминированный Swift ARC)    (Сборщик мусора Dart GC)     (Ручной MRC/ARC)
```

### Детальный разбор плюсов выбранной архитектуры:
1. **Абсолютная безопасность цепочки поставок:** В приложении отсутствуют сторонние библиотеки.
   Каждая строчка кода, компилируемая в исполняемый бинарный файл, находится непосредственно в
   данном репозитории и доступна для аудита безопасности.
2. **Нулевой сетевой след (True Zero-Network):** Приложение не линкуется с `CFNetwork.framework`
   или веб-движками. В отчете Apple Privacy Nutrition Labels приложение декларирует:
   **"Data Not Collected"**.
3. **Совместимость с жесткими лимитами памяти расширений:** Так как ядро скомпилировано в статическую
   библиотеку без сборщика мусора (GC), Share Extension и WidgetKit легко укладываются в лимиты
   ОС (120 МБ и 30 МБ соответственно).

### Детальный разбор минусов и нюансов:
1. **Производительность интерпретатора `wasmi`:** Программная интерпретация байткода WebAssembly
   работает медленнее, чем JIT-компиляция (на факторе от 3x до 8x в зависимости от типа вычислений).
   *Компромисс:* В контексте безопасности это сознательный и единственно возможный выбор, так как
   JIT-компиляция стороннего кода категорически запрещена правилами Apple App Store и несет риски
   аппаратных уязвимостей типа Spectre.
2. **Трудоемкость кастомного интерфейса:** Отказ от готовых компонентов библиотек (UIKit/Jetpack)
   потребовал написания собственной дизайн-системы, векторных глифов и обработчиков жестов.
   *Компромисс:* Обеспечивает абсолютную независимость от изменений системных стилей Apple и
   гарантирует единообразие визуального языка между iOS и Android версиями.

## Заключение

Архитектура iOS-версии Arca представляет собой гармоничный синтез максимальной параноидальной
изоляции на базе Rust и WebAssembly с современным эргономичным интерфейсом на SwiftUI.
Приложение полностью готово к сборке, статической проверке и развертыванию на тестовых стендах
macOS / iOS без необходимости внесения изменений в общие платформенно-независимые модули репозитория.
