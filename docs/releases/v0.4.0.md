# Arca 0.4.0 — Access: схема, связи и точный рентген; SmartArt и кодировки в презентациях; именные палитры (пре-релиз)

Продолжение [0.3.0](v0.3.0.md). Подпись та же, что у 0.3.0 (постоянный ключ, отпечаток SHA-256 сертификата `3b3b819dea6a02ffdea05ac7ce53df9b2bdf004dac3082c048557383cfaf737e`), поэтому 0.4.0 ставится поверх 0.3.0. Приложение по-прежнему не запрашивает ни одного разрешения.

## Что изменилось

* **Access: рентген решает по системному каталогу.** Макрос `AutoExec`, модули VBA, проект `VBAProject` и таблица `MSysAccessStorage` определяются по записям `MSysObjects` (макрос — тип `-32766`, модуль — `-32761`). База, в строках которой просто встречаются эти слова, больше не получает находку. Побайтовый поиск имён (ASCII и UTF-16LE) включается только когда каталог прочитан не целиком: файл повреждён, обрезан (в том числе посреди страницы), каталог не открылся или чтение остановил предел.
* **Access: схема, связи, схема связей.** В просмотре появился лист «Schema»: тип, размер, первичный ключ, «обязательное», атрибуты (автонумерация, вычисляемый, скрытый, индексированный) и описание каждого столбца. Режим «Показать страницами» рисует схему связей: таблицы-рамки со столбцами (PK/FK), линии `MSysRelationships` с отметками `1` и `∞`. Данные таблиц для схемы не читаются.
* **Строка таблицы целиком.** Нажатие на номер строки в сетке открывает её карточкой «столбец — значение»; для таблиц Access подписями служат имена столбцов.
* **Презентации.** Текст SmartArt (`ppt/diagrams/data*.xml`) попадает в просмотр и рисуется на странице слайда по кэшированному рисунку диаграммы. В бинарных `.ppt` однобайтовый текст (`TextBytesAtom`) читается в кодовой странице, названной набором символов шрифтов документа (CP1251, CP1250 и др.), а не как Latin-1; без шрифтов — Windows-1252. У кириллических букв в постраничном виде свои ширины, поэтому строки русских слайдов переносятся там, где их переносит просмотрщик. Тексты фигур, групп и таблиц ODP покрыты тестом.
* **Оформление Android.** Шесть именных палитр: Alabaster Studio, Obsidian Vault (чёрная для OLED, лист в постраничном виде переворачивается по светлоте с сохранением оттенка), Cashmere & Cappuccino, Sierra Blue & Slate, Emerald SecOps, Desert Titanium. Переключатель «Жидкое стекло» (по умолчанию выключен) делает карточки полупрозрачными глянцевыми панелями; размытия фона за панелью нет.
* **Сборка.** Флаги Wasm-гостя заданы в одном месте (`tools/guest-env.sh`) и общие для `build-guest.sh`, `check-reproducible.sh` и контейнерной сборки; библиотеки вшивают те самые байты, от которых посчитан хэш. Тест `the_embedded_guest_matches_the_digest_recorded_at_build_time` больше не зависит от порядка запуска тестов (он читал состояние движка, которое создавали другие тесты); 100 запусков из 100 проходят. Добавлен `tools/android/sign-release.sh` — подпись собранного пакета постоянным ключом.
* **Документация.** Описание напоминания о поддержке приведено к карточке на главном экране; «Показать страницами» описан для всех рисуемых форматов; список дополнительных реквизитов поддержки необязателен и не содержит заглушек (основная ссылка — Lava.top).

## Что в эту версию не вошло

* Таблицы стилей Word (DOCX `styles.xml`, ODT, RTF, DOC): цвет, размер и подсветка текста, отступы, межстрочные интервалы, рамки абзацев. Модель просмотра пока хранит жирность, курсив, подчёркивание, выравнивание и уровень списка.
* Постраничный вид текстовых документов (DOCX, ODT, RTF) и бинарных презентаций (PPT), показ картинок прямо в потоке документа.
* Нижняя панель навигации по документу (ползунок страниц, быстрый переход к оглавлению), закреплённая шапка столбцов и фильтр строк в таблицах Access.
* Visio: разбор и рисование VSDX/VSD остались такими, как в 0.3.0.

## Чего это не доказывает

* Проверки — компиляция, модульные тесты, тесты JNI на хосте, `check-android` и сборка пакета. Устройства и эмуляторы не использовались: палитры, «Жидкое стекло» и карточка строки не просматривались на экране.
* Схема связей Access проверена на синтетических базах и на базах-образцах Jackcess; базы, созданные самим Access, в набор не входят. Раскладка `MSysRelationships` и `MSysQueries` взята из описания Jackcess.
* Ширины кириллических букв — оценка по метрикам Arial-подобного шрифта; на странице текст подгоняется под заявленную ширину строки.
* Нужные для вердикта детекторы по-прежнему проверены на созданных нами враждебных входах; корпус реальных вредоносных образцов в набор не входит.

# Arca 0.4.0 — Access schema, relationships and a catalog-first X-ray; SmartArt and code pages in presentations; named palettes (pre-release)

Continues [0.3.0](v0.3.0.md). The signing key is the same as in 0.3.0 (certificate SHA-256 `3b3b819dea6a02ffdea05ac7ce53df9b2bdf004dac3082c048557383cfaf737e`), so 0.4.0 installs over 0.3.0. The app still requests no permission at all.

## What changed

* **Access: the X-ray decides from the system catalog.** The `AutoExec` macro, VBA modules, the `VBAProject` object and the `MSysAccessStorage` table are identified from the `MSysObjects` rows (macro: type `-32766`, module: `-32761`). A database that merely contains these words in its data no longer gets a finding. The byte search for the names (ASCII and UTF-16LE) runs only when the catalog was not read completely: the file is damaged or cut off (including in the middle of a page), the catalog could not be opened, or a limit stopped the read.
* **Access: schema, relationships, relationship diagram.** The preview has a "Schema" sheet: type, size, primary key, required, attributes (autonumber, calculated, hidden, indexed) and description of every column. "Show as pages" draws the relationship diagram: a box per table with its columns (PK/FK) and the `MSysRelationships` lines marked `1` and `∞`. No table data is read for it.
* **A whole row as a card.** Tapping the number of a grid row opens it as "column — value"; for Access tables the labels are the column names.
* **Presentations.** SmartArt text (`ppt/diagrams/data*.xml`) enters the reading view and is drawn on the slide page from the diagram's cached drawing. In binary `.ppt` files, one-byte text (`TextBytesAtom`) is read in the code page named by the character set of the document's fonts (CP1251, CP1250, …) instead of Latin-1, and in Windows-1252 when there are no fonts. Cyrillic letters have their own widths in the page view, so lines of Russian slides wrap where a viewer wraps them. Text of ODP shapes, groups and tables is covered by a test.
* **Android appearance.** Six named palettes: Alabaster Studio, Obsidian Vault (true black for OLED; the sheet of a page view is inverted in lightness with hue kept), Cashmere & Cappuccino, Sierra Blue & Slate, Emerald SecOps, Desert Titanium. The "Liquid Glass" switch (off by default) turns cards into translucent glossy panels; nothing behind a panel is blurred.
* **Build.** The Wasm guest flags live in one place (`tools/guest-env.sh`), shared by `build-guest.sh`, `check-reproducible.sh` and the container build; the libraries embed exactly the bytes whose hash was computed. The test `the_embedded_guest_matches_the_digest_recorded_at_build_time` no longer depends on test order (it read engine state that other tests created); 100 runs out of 100 pass. `tools/android/sign-release.sh` signs a built package with the permanent key.
* **Documentation.** The support reminder is described as the home-screen card; "Show as pages" is described for every drawn format; the list of extra support addresses is optional and has no placeholders (the main link is Lava.top).

## Checksums (built from a clean export of the commit, `ARCA_RELEASE=1`)

See the table above. The package hash changes when it is signed; it is written to `arca-0.4.0.apk.sha256` next to the signed file.

## Not in this version

* Word style sheets (DOCX `styles.xml`, ODT, RTF, DOC): text colour, size and highlight, indents, line spacing, paragraph borders. The reading model keeps bold, italic, underline, alignment and list level.
* Page view of text documents (DOCX, ODT, RTF) and binary presentations (PPT), and pictures inside the flow of a document.
* A bottom navigation bar (page slider, quick jump to the contents), a pinned column header and a row filter for Access tables.
* Visio: reading and drawing of VSDX/VSD are as in 0.3.0.

## What this does not prove

* The checks are compilation, unit tests, host-side JNI tests, `check-android` and the package build. No devices or emulators were used: the palettes, Liquid Glass and the row card have not been looked at on a screen.
* The Access relationship diagram was checked on synthetic databases and Jackcess sample databases; databases written by Access itself are not in the test set. The layouts of `MSysRelationships` and `MSysQueries` come from the Jackcess description.
* Cyrillic widths are an estimate from Arial-like metrics; the page view fits each run to the width the document declares.
* The detectors behind the verdict are still tested on hostile inputs we built ourselves; a corpus of real malware is not in the test set.
