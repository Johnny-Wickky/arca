# Arca — архитектура

> Статус: **Фазы 1–2 реализованы** (архитектура, лицензирование, песочница,
> рентген угроз, стерилизатор OOXML, модуль атрибуции). Фазы 3–5 (граф сцены,
> парсеры форматов для отображения, мобильный UI, расширенный набор
> adversarial-тестов) описаны здесь как план и помечены *(Фаза N)*.

## 1. Принципы

1. **Каждый файл — враждебный эксплойт.** Ни один байт документа не
   интерпретируется вне двух контуров изоляции: memory-safe Rust и
   эфемерной Wasm-песочницы без импортов.
2. **Ноль `unsafe`, ноль C/C++.** Весь собственный код —
   `#![forbid(unsafe_code)]`; в графе зависимостей нет `*-sys`-крейтов и C-сборки.
   Единственное ограниченное исключение — атрибут `#[unsafe(no_mangle)]` на
   пяти экспортах Wasm-гостя (§4.6).
3. **Детерминированные отказы.** Ни `unwrap`/`expect`/`panic` в рабочем коде,
   лимит на всё, что зависит от входа: размер, глубина, число элементов,
   коэффициент сжатия, топливо CPU, память.
4. **Никакой сети.** Ядро не содержит сетевого кода; приложению не нужно
   разрешение `INTERNET`. Внешние ссылки документа только перечисляются в
   отчёте. Ссылки на пожертвования открывает системный браузер, и только
   после явного нажатия пользователя.
5. **Без утечек.** Буферы документов и результаты обнуляются (`zeroize`).
   Логи не содержат содержимого документов и персональных метаданных: ядро
   вообще ничего не логирует.

Граф зависимостей реализованных крейтов (стрелка — «зависит от»):

```text
arca-attribution ─► arca-digest ◄─ arca-sandbox ─► arca-abi
                                           ▲    └─► wasmi, wasmi_core, zeroize
arca-guest-xray ─► arca-xray ─► arca-container ─► arca-digest
        └─► arca-abi ◄──┘            └─► quick-xml, miniz_oxide
```

`arca-sandbox` не зависит от `arca-xray`: хост песочницы не содержит ни
одного парсера документов. Отчёт из песочницы декодирует тонкий слой
`arca_guest_xray::decode_report` с жёсткими лимитами декодирования.

## 3. Два контура изоляции

```text
 ┌──────────────────────────── процесс приложения ─────────────────────────────┐
 │  Flutter UI (Фаза 4) ──FFI──► arca-ffi (Фаза 4)                            │
 │                                   │ байты файла (только чтение)             │
 │                                   ▼                                         │
 │  ┌──────────── arca-sandbox (хост, Safe Rust) ───────────────────────────┐ │
 │  │ 1. проверка SHA-256 модуля по allow-list (ModulePin)                    │ │
 │  │ 2. валидация модуля, отказ при ЛЮБОМ импорте, start-функции, лишних     │ │
 │  │    proposals                                                            │ │
 │  │ 3. новый Engine + Store на один вызов, отдельный рабочий поток          │ │
 │  │ 4. лимиты: память 128 МиБ, топливо CPU, глубина рекурсии, стек          │ │
 │  │  ┌────────── Wasm-гость (wasm32-unknown-unknown, 0 импортов) ──────────┐ │ │
 │  │  │ arca-guest-xray = arca-xray + arca-container                     │ │ │
 │  │  │ нет сети, ФС, таймера, случайности, IPC — только вычисления         │ │ │
 │  │  └─────────────────────────────────────────────────────────────────────┘ │ │
 │  │ 5. копия результата с проверкой границ → конверт ARCA → wire-декодер    │ │
 │  │ 6. обнуление памяти гостя, уничтожение Store                            │ │
 │  └────────────────────────────────────────────────────────────────────────┘ │
 └──────────────────────────────────────────────────────────────────────────────┘
```

**Контур 1 — Safe Rust.** Исключает целые классы уязвимостей парсеров
(переполнение буфера, use-after-free, double free). Остаются логические
ошибки и отказ в обслуживании; их закрывают лимиты и контур 2.

**Контур 2 — эфемерная песочница.** Даже если в парсере есть логическая
ошибка, позволяющая документу управлять его поведением, у гостя нет никакой
возможности воздействовать на мир: модуль без импортов может только считать в
своей линейной памяти. Время и память ограничены, после вызова от экземпляра
не остаётся ничего.

## 4. Крейты

### 4.1 `arca-digest`
SHA-256 (FIPS 180-4, проверка по векторам NIST) и CRC-32 (IEEE 802.3), `no_std`,
без зависимостей. SHA-256 пиннингует Wasm-модули и отпечаток уведомления об
авторстве. CRC-32 используется только для целостности ZIP и записи
статистики «Паспорта».

### 4.2 `arca-container` — защищённые контейнеры
| модуль | что делает | ключевые защиты |
|---|---|---|
| `zip` | чтение ZIP/ZIP64 по центральному каталогу | EOCD/ZIP64-валидация; согласие CD ↔ локальных заголовков (имя, метод, размеры, CRC); запрет перекрытий записей; канонизация имён, отказ при `../`, абсолютных путях, `\`, буквах дисков, NUL, управляющих символах, дубликатах без учёта регистра; отказ при symlink-атрибутах; коэффициент сжатия ≤ 100:1 (с запасом 1 МиБ для мелких частей); обнаружение «лживого» размера; общий бюджет распаковки на документ (`InflateBudget`, 1 ГиБ и агрегатный коэффициент) |
| `zip::writer` | детерминированная запись (стерилизатор) | фиксированная метка времени, проверка имён |
| `cfb` | OLE2 Compound File | проверка заголовка и сектора; DIFAT/FAT/miniFAT с обнаружением циклов; ограничение числа записей каталога, размера потоков и глубины; обнаружение «осиротевших» записей |
| `cfb::writer` | детерминированная запись CFB | — |
| `xml` | безопасный потоковый XML поверх `quick-xml` | `DOCTYPE` запрещён целиком (XXE, Billion Laughs); только пять предопределённых сущностей и числовые ссылки; глубина ≤ 64; лимиты атрибутов, событий, длины имён и входа; ровно один корень; перекодировка UTF-16 |
| `xml::rewrite` | перезапись с сохранением исходных байтов вне изменённых узлов | основа стерилизатора |
| `text`, `bytes`, `budget` | безопасное чтение little-endian, кодовые страницы, обезвреживание bidi-символов при показе | — |

### 4.3 `arca-abi` — контракт гостя (версия 1)

| экспорт | сигнатура | смысл |
|---|---|---|
| `memory` | память | единственная память гостя |
| `arca_abi_version` | `() -> i32` | должна вернуть `1` |
| `arca_input_reserve` | `(len) -> ptr` | гость выделяет буфер под вход |
| `arca_run` | `(len) -> status` | обработка |
| `arca_output_ptr` / `arca_output_len` | `() -> i32` | где лежит результат |

Результат — конверт `"ARCA" | u16 версия | u16 вид | u32 длина | полезная нагрузка`.
Нагрузка кодируется собственным wire-кодеком с ограниченным декодированием
(`DecodeLimits`: длина строк, число элементов, глубина): данные из песочницы
считаются недоверенными, ведь скомпрометированный гость мог записать что угодно.

### 4.4 `arca-xray` — «Рентген безопасности»

`scan(bytes, &ScanPolicy) -> XRayReport` — один проход без исполнения чего-либо.

**Определение формата** — только по сигнатурам (ZIP `PK`, OLE2
`D0 CF 11 E0 A1 B1 1A E1`, `%PDF`, `{\rtf`, Jet/ACE, MZ/ELF/Mach-O), уточнение
по `[Content_Types].xml`, `mimetype` ODF и CLSID корня OLE2. Расширение файла не
используется. Поддерживаемые семейства: OOXML (docx/docm/dotx/dotm, xlsx/xlsm/
xltx/xltm/xlsb/xlam, pptx/pptm/ppsx/ppsm/potx/potm, vsdx/vsdm/шаблоны, xps), ODF
(odt/ods/odp/odg), OLE2 (doc/xls/ppt/vsd/msg/msi, зашифрованный OOXML), RTF,
PDF, Access (Jet3/Jet4/ACE), текстовые (txt/csv/tsv/md/html/flat XML), ZIP,
исполняемые файлы (отказ).

**Детекторы** (каждая находка — типизированный `ThreatKind` с категорией и
важностью):

* *Активное содержимое:* VBA (MS-OVBA: распаковка, разбор `dir`, извлечение
  исходников, автозапуск, подозрительные вызовы, признаки VBA stomping), XLM
  Excel 4.0 (макролисты, `Auto_Open`), StarBasic/скрипты ODF, DDE в полях Word
  (включая обфускацию `QUOTE`) и в формулах, `WEBSERVICE`/`CALL`/`REGISTER`,
  OLE-объекты и пакеты (`Ole10Native`, опасные расширения, таблица опасных
  CLSID — Equation Editor и др.), ActiveX, callbacks ленты, действия PowerPoint
  `ppaction://program`, `RUNADDON` в Visio, RTF `objdata`/`objupdate`, PDF
  JavaScript/Launch/OpenAction/вложения/RichMedia, CSV-инъекции формул, активный
  HTML.
* *Внешнее содержимое (SSRF, трекеры, NTLM-утечки):* удалённые шаблоны
  (`attachedTemplate`), внешние картинки и фреймы, связанные OLE-объекты,
  внешние книги, подключения данных, `INCLUDEPICTURE`/`INCLUDETEXT`, UNC-пути,
  опасные схемы URI (`ms-msdt:` и т. п.), источники слияния, удалённые действия
  PDF, `hyperlinkBase`. Каждый URL попадает в `external_refs` с
  классификацией цели.
* *Сокрытие:* скрытые и «очень скрытые» листы, скрытые строки и столбцы,
  скрытый и невидимый (белым по белому, микрошрифт) текст, скрытые слайды,
  осиротевшие OLE-записи и данные ZIP, полиглоты (PDF+ZIP и др.), хвостовые
  данные, bidi-переопределения в именах, переменные документа.
* *Утечки приватности:* автор, организация, компьютер, локальные пути,
  принтеры, ревизии, комментарии, идентификаторы сеансов правки (rsid),
  пользовательские свойства, суммарное время правки, версии ПО.
* *Структура:* повреждённые контейнеры, бомбы, обход путей, XML-атаки,
  расхождения парсеров, несоответствие типа содержимого, замаскированные
  исполняемые файлы, шифрование.

**Вердикт** (`Verdict`):
`Clean` → `HiddenTrackers` (есть внешнее содержимое) →
`ActiveContentNeutralized` (активная нагрузка или критическое внешнее
содержимое, например удалённый шаблон) → `Rejected` (бомба, обход путей,
XML-атака, исполняемый файл и т. п. — документ не открывается).

**Стерилизатор** (`sanitize`) — *One-Tap Sanitize* для OOXML: удаляет части по
ролям (VBA, ActiveX, OLE, макролисты, customXml, миниатюры, комментарии),
внешние и висячие связи; переписывает XML: нейтрализует поля (DDE,
`INCLUDE*`, `MACROBUTTON`), принимает ревизии, удаляет комментарии, rsid и
метаданные, удаляет опасные формулы Excel с сохранением закэшированных значений,
действия PowerPoint, активные формулы Visio; меняет типы содержимого на
безмакросные (`docm` → `docx`). Результат детерминирован, идемпотентен и
**сканируется повторно**: копия выдаётся, только если в ней не осталось
активного или внешнего содержимого уровня Medium и выше.
Остальные форматы *(Фаза 3)* стерилизуются через граф сцены: «сплющенный» PDF
требует рендерера.

### 4.5 `arca-sandbox` — хост песочницы

| свойство | механизм |
|---|---|
| нет системного доступа | модули с **любым** импортом отвергаются до инстанцирования |
| нет внедрения кода | исполняются только модули с SHA-256 из allow-list; валидация всегда включена; `start` запрещён; лишние proposals выключены |
| CPU | топливо: `2·10⁹ + 4000 × байт входа`, максимум `4·10¹¹`; исчерпание — детерминированная ловушка |
| память | `ResourceLimiter`: 128 МиБ линейной памяти, 100 000 элементов таблиц |
| стек | лимит глубины рекурсии интерпретатора (4096) и высоты стека значений (8 МиБ) |
| ввод-вывод | вход ≤ 512 МиБ, выход ≤ 64 МиБ, модуль ≤ 32 МиБ; регион результата проверяется на границы памяти гостя |
| эфемерность | `Engine`/`Store`/память — на один вызов; память гостя обнуляется; результат в `Zeroizing` |
| локализация сбоев | гость выполняется в отдельном потоке (`std::thread::scope`); паника интерпретатора → `SandboxError::WorkerPanicked` |

`wasmi` (интерпретатор) выбран вместо JIT-рантаймов, потому что iOS не даёт
сторонним приложениям исполняемую память (W^X), а интерпретатор не пускает
код гостя в машинный поток инструкций вовсе.

### 4.6 `arca-guest-xray` — гость
`arca-xray`, собранный под `wasm32-unknown-unknown` профилем `guest`
(`panic = "abort"`, `opt-level = "s"`, LTO). Модуль имеет **ноль импортов**
(проверяется в CI и при каждом запуске). Экспорт символа требует атрибута
`#[unsafe(no_mangle)]`, который линт `unsafe_code` считает небезопасным, поэтому
крейт использует `deny` вместо `forbid` и разрешает его ровно на пяти
функциях экспорта. Блоков `unsafe` нет; `tools/check-unsafe.sh` проверяет и это,
и идентичность остальных линтов. Отчёт гостя совпадает с нативным сканированием
(тест `guest_report_equals_native_report` и прогон по корпусу).

### 4.7 `arca-attribution` — атрибуция и «Паспорт Хранителя»
* `upstream.rs` — неизменяемые константы оригинальных создателей
  (`UPSTREAM_AUTHORS`, `UPSTREAM_DONATION_LINKS`, тексты уведомления, заголовки
  карточек). Их SHA-256-отпечаток закреплён в `UPSTREAM_FINGERPRINT`;
  `build.rs` останавливает сборку при любом расхождении. Это защита от
  случайного удаления, а не DRM: юридическую силу имеет лицензионное условие.
* `fork.rs` — строгий разбор `fork_attribution.toml` (подмножество TOML, только
  известные ключи, только `https://`, без учётных данных, управляющих и
  bidi-символов, запрет выдавать себя за оригинал). Тот же код выполняется в
  `build.rs`: некорректный файл форка не компилируется.
* `screen.rs` — модель экрана «О проекте и Поддержка»: карточка «Создатели
  оригинального ядра Arca (Поддержать)» всегда первая, карточка
  «Команда поддержки модификации / Форка (Поддержать)» добавляется в форке,
  у карточек нет индивидуального стиля. `check_upstream_prominence` проверяет
  отрисованную раскладку в golden-тестах UI.
* `passport.rs` — локальная статистика (36-байтовая запись с CRC, без часов и
  ввода-вывода в ядре) и текст «Вы пользуетесь Arca уже 30 дней…» с
  правилами русских склонений.
* `integrity.rs` — отпечаток и блокировщики релиза: `ARCA_RELEASE=1` не
  собирается, пока остались домены-заглушки (`.invalid`, `.example`, …).

Идея обязательной атрибуции в интерфейсе заимствована из CPAL-1.0 (Exhibit B),
но требование мягче: экран «О проекте и Поддержка», а не заставка при каждом
запуске. Юридическая основа — дополнительные условия по разделу 7 AGPLv3, а
не CPAL: CPAL несовместима с GPL.

## 5. Поток данных при открытии документа

1. UI получает байты файла (системный picker; приложение не имеет широкого
   доступа к ФС).
2. `arca-ffi` *(Фаза 4)* передаёт срез в `Sandbox::run` с модулем
   `arca_guest_xray.wasm`, вшитым в приложение, и его закреплённым SHA-256.
3. Песочница копирует вход в память гостя, гость выполняет `scan`, хост
   копирует конверт с проверкой границ и уничтожает экземпляр.
4. `decode_report` декодирует `XRayReport` с лимитами.
5. Вердикт `Rejected` → документ не отображается, HUD объясняет причину.
   Иначе *(Фаза 3)* отдельный гость-парсер формата строит `ArcaRenderTree`,
   внешние ресурсы которого уже вырезаны; UI рисует граф сцены.
6. «Создать стерильную копию» → `sanitize` (в песочнице, тем же механизмом) →
   повторный рентген → экспорт через системный диалог «Поделиться».
7. Закрытие документа → буферы обнуляются.

## 7. Цепочка поставок

| крейт | версия | лицензия | назначение |
|---|---|---|---|
| `wasmi`, `wasmi_core`, `wasmi_ir`, `wasmi_collections` | 2.0.0 | MIT/Apache-2.0 | интерпретатор Wasm |
| `wasmparser` | 0.228.0 | Apache-2.0 WITH LLVM-exception / Apache-2.0 / MIT | валидация модулей |
| `quick-xml` | 0.42.0 | MIT | потоковый XML |
| `miniz_oxide` + `adler2` | 0.9.0 / 2.0.1 | MIT/Zlib/Apache-2.0 | DEFLATE (крейт `forbid(unsafe_code)`) |
| `zeroize` | 1.9.1 | Apache-2.0/MIT | обнуление памяти |
| `memchr`, `bitflags`, `spin`, `libm` | транзитивные | MIT/Unlicense/Apache-2.0 | — |

Правила:
* только чистый Rust, никаких `*-sys`, `cc`, `cmake`, `bindgen` (`deny.toml`,
  `tools/check-unsafe.sh`);
* прямые зависимости закреплены точно (`=x.y.z`), функции по умолчанию
  выключены, включено только проверенное;
* **`Cargo.lock`**: файл не поставляется в этом архиве, потому что разработка
  шла на офлайн-копиях исходников без контрольных сумм crates.io. Перед первым
  коммитом выполните `cargo generate-lockfile`, проверьте, что граф совпадает с
  таблицей выше (`cargo tree`), и закоммитьте файл; CI затем использует `--locked`;
* `cargo deny check all` в CI: лицензии, RustSec advisories, запреты, источники;
* зависимости содержат внутренний `unsafe` (`wasmi`, `quick-xml`, `memchr`,
  `zeroize`). `forbid(unsafe_code)` распространяется на код Arca; доверие к
  зависимостям — осознанное и минимальное, их список — вся доверенная база.

## 8. Решения и отклонения

| решение | обоснование |
|---|---|
| `wasmi`, а не `wasmtime` | iOS не допускает JIT; интерпретатор проще аудировать |
| одна копия входа в гостя и одна копия результата вместо zero-copy | у Wasm-гостя нет доступа к памяти хоста по определению; копия — цена изоляции. Zero-copy применим на стыке Flutter ↔ Rust (`arca-ffi`, Фаза 4) |
| модуль компилируется заново при каждом запуске | полная эфемерность; около 16 мс. Кэширование проверенного `Module` возможно позже без ослабления изоляции экземпляров |
| запас 1 МиБ в проверке коэффициента сжатия | мелкие однородные XML-части законно сжимаются сильнее 100:1; абсолютный объём ограничен общим бюджетом |
| `deny` вместо `forbid` в `arca-guest-xray` | см. §4.6 |
| `arca-ffi` *(Фаза 4)* | `flutter_rust_bridge` генерирует FFI-glue с `extern "C"`; он будет изолирован в отдельном крейте без логики разбора, по той же схеме, что и гость |
| стерилизатор только для OOXML в Фазе 2 | бинарные форматы и PDF стерилизуются через пересборку из `ArcaRenderTree` (Фаза 3); сейчас для них возвращается `SanitizeError::Unsupported` |
| эвристики в бинарных форматах | VBA stomping, поля Word Binary, PPT-записи — эвристики с низким уровнем ложных срабатываний (проверено на документах LibreOffice). Они не заменяют полный парсер формата Фазы 3 |
| обнуление памяти | обнуляются буферы, которыми владеет Arca, и вся память гостя. Копии, которые аллокатор мог оставить при перераспределении `Vec` внутри зависимостей, гарантированно не стираются; память гостя стирается целиком, поэтому разбор там безопаснее |
| зашифрованные документы | обнаруживаются (`EncryptedDocument`), но в Фазе 2 не расшифровываются |

## 9. Сборка и проверка

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets          # ноль предупреждений
cargo test --workspace
tools/check-unsafe.sh

# Wasm-гость и сквозные тесты в песочнице
cargo build -p arca-guest-xray --target wasm32-unknown-unknown --profile guest
ARCA_GUEST_XRAY_WASM=target/wasm32-unknown-unknown/guest/arca_guest_xray.wasm \
    cargo test -p arca-guest-xray --test e2e_sandbox -- --nocapture

# CLI для ручной проверки
cargo run -p arca-xray --example xray -- scan suspicious.docm
cargo run -p arca-xray --example xray -- sanitize in.docm out.docx

# Атрибуция форка и релизный контроль
ARCA_FORK_ATTRIBUTION=$PWD/fork_attribution.example.toml cargo test -p arca-attribution
ARCA_RELEASE=1 cargo build -p arca-attribution --release   # падает, пока есть заглушки
```
