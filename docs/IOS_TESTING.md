# Проверка iOS-клиента на Mac и iPhone

Инструкция для того, кто впервые запускает Arca на iOS (задача «Первый живой прогон iOS-клиента на MacBook и iPhone»). Код клиента (`app/`, SwiftUI) и C-мост (`crates/arca-ffi`) собираются и проверяются на macOS-раннере GitHub Actions (`.github/workflows/ios.yml`), но **на реальном устройстве ещё не запускались**. Здесь описано, что поставить, какие команды выполнить и что записать, чтобы результат можно было превратить в исправления.

Устройство и архитектура: [`docs/IOS_ARCHITECTURE.md`](IOS_ARCHITECTURE.md), [`app/README.md`](../app/README.md).

## 1. Что нужно

| Что | Зачем |
|---|---|
| Mac на Apple silicon или Intel, macOS 14+ | сборка |
| Xcode 15.4 или новее (с iOS-симуляторами) | сборка, подпись, запуск на iPhone |
| [rustup](https://rustup.rs) | нужный Rust ставится сам из `rust-toolchain.toml` (1.97.0, с iOS-целями) |
| XcodeGen: `brew install xcodegen` | делает `Arca.xcodeproj` из `app/project.yml` |
| iPhone с iOS 16 или новее, кабель | проверка на устройстве |
| Apple ID (бесплатного достаточно) | подпись приложения на свой iPhone |

На iPhone: **Настройки ▸ Конфиденциальность и безопасность ▸ Режим разработчика** — включить (iPhone перезагрузится).

## 2. Быстрый путь: собрать и запустить

```bash
git clone https://github.com/Johnny-Wickky/arca.git
cd arca
rustup show                          # поставит Rust 1.97.0 и цели из rust-toolchain.toml
brew install xcodegen
bash tools/build-guest.sh            # Wasm-гость (парсер документов, он вшивается в библиотеку)
bash tools/ios/build-app.sh project  # собирает ArcaCore.xcframework и пишет app/Xcode/Arca.xcodeproj
open app/Xcode/Arca.xcodeproj
```

В Xcode: цель **Arca** ▸ **Signing & Capabilities** ▸ выбрать свой **Team** (при необходимости сменить Bundle Identifier на уникальный, например `org.arca.viewer.<ваше имя>`) ▸ вверху выбрать iPhone ▸ **Run** (⌘R).

При первом запуске на устройстве iOS попросит доверять разработчику: **Настройки ▸ Основные ▸ VPN и управление устройством ▸ ваш Apple ID ▸ Доверять**.

Симулятор вместо iPhone: выбрать любой iPhone в списке устройств Xcode и нажать Run, либо из готового архива (см. п. 3).

## 3. Готовые сборки из CI

Каждый прогон `ios` в GitHub Actions выкладывает артефакты:

* `arca-ios-app` — `Arca-simulator.app.zip` (для симулятора) и `Arca-unsigned.ipa` (неподписанный, для устройства: подписывается вашим Apple ID, например утилитой для sideloading);
* `ArcaCore.xcframework.zip` — Rust-ядро для Xcode;
* `ios-logs` — полные логи `xcodebuild` и результат тестов (`.xcresult`): читать, если какой-то шаг упал.

Симулятор:

```bash
unzip Arca-simulator.app.zip
xcrun simctl boot "iPhone 15" || true
xcrun simctl install booted Arca.app
xcrun simctl launch booted org.arca.viewer
```

## 4. Автоматическая проверка на своём Mac

```bash
bash tools/ios/check-ios.sh
```

Скрипт делает по порядку: проверка «ноль сети, ноль телеметрии» в исходниках Swift ▸ компиляция пакета `ArcaKit` под симулятор ▸ сборка `ArcaCore.xcframework` ▸ **тесты Swift на симуляторе** (в том числе `ArcaEngineTests`: запуск настоящего ядра и Wasm-гостя, самотест, открытие документов из `tests/fixtures`, пароль, стерильная копия) ▸ сборка приложения для симулятора и для устройства. Логи — в `target/ios-logs/`, результат тестов — `target/ios-test.xcresult`.

## 5. Что проверить на iPhone

Файлы берите из `tests/fixtures/` (безопасные тестовые документы; описание — `tests/fixtures/README.md`). Передать на iPhone: AirDrop, «Файлы» (iCloud Drive) или `xcrun devicectl device copy to`. Открывать: в приложении «Файлы» нажать на файл ▸ «Поделиться» ▸ **Arca**; либо в Arca кнопка «Нажмите для выбора файла».

| № | Проверка | Ожидается |
|---|---|---|
| 1 | Запуск, главный экран | экран с щитом и зоной выбора файла, без падений |
| 2 | Открыть по одному: `report.docx` `.doc` `.odt` `.rtf` `.pdf` `.txt`, `sheet.xlsx` `.xls` `.ods` `.csv`, `slides.pptx` `.ppt` `.odp`, `deck-rich.pptx`, `charts.pptx`, `drawing.vsdx`, `access-2016.accdb` | экран «Рентген безопасности» с вердиктом; «Безопасный просмотр» показывает содержимое |
| 3 | Тот же файл через «Поделиться ▸ Arca» из «Файлов» и из Почты/Telegram | открывается так же (точка входа `onOpenURL`) |
| 4 | Перетащить файл на зону выбора (iPad, Split View) | открывается |
| 5 | Зашифрованные: `enc-agile.docx` (пароль `пароль-123`), `enc-agile.xlsx` (`s3cret`), `enc-standard.docx` (`Password1234_`), `enc-aes-256.pdf` (`user-256`) | в отчёте кнопка «Ввести пароль»; с верным паролем документ открывается, с неверным — остаётся запрос |
| 6 | «Стерильная копия в один тап» на `report.docx` и `lo-rich.doc` | лист «Стерильная копия создана», «Поделиться» отдаёт новый файл, который открывается в Pages/Word |
| 7 | Макросы: файлы лаборатории (п. 6) | «Рентген» показывает макрос и объяснение; «Копировать» кладёт исходник в буфер |
| 8 | Картинки в документах (`deck-rich.pptx`) | значок картинки открывает просмотр во весь экран |
| 9 | Экран «Паспорт»: карточка создателей ядра **первая**, темы переключаются, лицензия открывается | да |
| 10 | Тёмная/светлая системная тема, поворот, iPad Stage Manager | интерфейс читается, ничего не обрезается |
| 11 | Большой файл (`tools/fixtures/make_heavy_deck.py`, около 15 МБ) | не падает; запишите пик памяти в Xcode (Debug navigator ▸ Memory) и время до результата |
| 12 | Режим полёта + **Настройки ▸ Конфиденциальность ▸ Отчёт о конфиденциальности приложений** (включить «Записывать активность приложений», поработать с Arca, потом открыть отчёт) | у Arca нет сетевых обращений и доступа к датчикам; ссылка поддержки открывается только по нажатию и только в браузере |
| 13 | Закрыть документ и смотреть на память | после «закрыть» память возвращается (ручное зануление буферов в ядре) |

Файлы лаборатории атак (пятьдесят обезвреженных образцов) выгружаются командой `ARCA_LAB_OUT=/путь/к/папке cargo test -p arca-xray malware_lab`; антивирус Windows может их удалять, поэтому делайте это на Mac. Это не вирусы, но по виду они такие, и «Файлы» могут показывать их с предупреждением.

### Что на iOS пока не сделано (не считать багом прогона)

* строки интерфейса только на русском, переключателя RU/EN нет;
* постраничный вид (рисунок страницы PDF/слайда) не подключён: `renderPage` есть в движке, но интерфейс его не вызывает;
* нет Share Extension и виджетов (описаны в `docs/IOS_ARCHITECTURE.md` как план);
* нет блокировки скриншотов и размытия в переключателе приложений;
* нет иконки приложения;
* просмотр большого документа каждый раз заново запускает песочницу на каждую порцию — прокрутка может быть тяжёлой, запишите, насколько.

## 6. Что записать для каждой проблемы

1. **Устройство и версия:** модель iPhone/iPad, версия iOS, симулятор это или устройство.
2. **Версия Arca:** `git rev-parse --short HEAD` (или имя артефакта и номер прогона CI).
3. **Файл:** имя из `tests/fixtures` (или как получен), формат, размер.
4. **Шаги:** что нажимали, что ожидали, что получилось.
5. **Скриншот или запись экрана** (боковая кнопка + громкость вверх).
6. **Консоль Xcode:** окно **Debug area** во время запуска (⇧⌘Y) или **Window ▸ Devices and Simulators ▸ Open Console**; для симулятора — `xcrun simctl spawn booted log stream --predicate 'process == "Arca"'`.
7. **Отчёт о падении**, если приложение закрылось: **Настройки ▸ Конфиденциальность и безопасность ▸ Аналитика и улучшения ▸ Данные аналитики** ▸ файл `Arca-…ips`; либо в Xcode **Window ▸ Organizer ▸ Crashes**. Отправлять его вручную: приложение само ничего никуда не отправляет.

Завести задачу: **Issues ▸ New issue ▸ «iOS: баг живого прогона»** (шаблон просит ровно эти поля). Критичные (падение при запуске, при открытии любого файла, тихий «чистый» вердикт у заведомо опасного файла) отметить сразу и написать в чат: это блокеры релиза.

## 7. Если сборка не идёт

| Симптом | Причина и что делать |
|---|---|
| `xcodegen: command not found` | `brew install xcodegen` |
| `no iPhone simulator is installed` | Xcode ▸ Settings ▸ Platforms ▸ скачать iOS Simulator |
| `Undefined symbols … _arca_…` при линковке | не собран `app/Frameworks/ArcaCore.xcframework`: `bash tools/ios/build-xcframework.sh` |
| `redefinition of module 'ArcaCore'` | в `xcframework` остался `module.modulemap`: пересобрать XCFramework скриптом (он кладёт только `arca.h`) |
| `Signing for "Arca" requires a development team` | в Xcode выбрать Team у цели Arca |
| `required symbol … missing from device library` | пересобрать; проверка символов читает таблицу через `llvm-nm` из Rust (Xcode `nm` не читает объекты свежего LLVM) |
| Приложение запускается и сразу закрывается на устройстве | консоль Xcode и отчёт о падении (п. 6); частая причина — не включён «Режим разработчика» или не принят сертификат |
